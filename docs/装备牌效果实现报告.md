**项目**:机斗战甲 / Battle-GEAR-S(Godot 4.6 战棋)
**任务**:实现 `new_logic/装备牌-N_效果与逻辑详解.txt` 中 part_001~042(7套×6部位)的全部效果,使其在游戏中真正可用(含 UI 交互)
**权威文档**:`机斗战甲规则书.txt`、`行动牌的效果与逻辑.txt`、`各动作的生命周期与时点.txt`、`装备牌-N_效果与逻辑详解.txt`
**完成范围**:架构扩展 A1-A8 + 量产 B + 联邦/帝国/重甲/机动/狙击/近战 C-H + UI 接线 I1-I2 + 测试 J

## 一、设计原则与硬约束(贯穿全程)

1. **全量42张一次性实现**,按套装分阶段(量产→联邦→帝国→重甲→机动→狙击→近战),共用约31个 effect_id(同型效果共用)。
2. **全面弃用 hook**:装备效果逻辑全走 Action Engine 的动作+时点体系(`DISCARD_BEFORE/AFTER/SETTLE`、`ATTACK_BEFORE/PRE/AT/AFTER/SETTLE`、`DAMAGE_REDIRECT_WINDOW` 等),不用 `effect_engine.fire_hook`。消息显示层也迁移。
3. **派生值效果查询时实时重算**:`MechState.get_armor/get_total_power` + `MechSlotState.get_effective_armor` 调用时扫描该机甲已设置装备的 effect 重新计算,不持久化 modifier、不注册监听器,装备离场自动失效。
4. **损伤转移用一次性汇总弹窗**(非逐点):`damage_change` 动作 fire `DAMAGE_REDIRECT_WINDOW` 时点,转移效果监听并弹汇总窗选转移点数。
5. **每回合1次**用 `ActionEffect.once_per_turn_key` 字段,scope=turn_number(换回合自动失效)。
6. **装备效果走新 ActionEffect 体系**(仿 `GeneratedActionEffects.gd`),不照搬 `GeneratedPilotEffects.gd` 的 legacy hook 模式。
7. **近战头部类型转换**:attack record 加 `effective_weapon_type` 字段(默认=实体武器 kind),近战头部在 ATTACK_BEFORE 改写,其他效果(狙击范围+1、近战右臂弃牌+威力)读它判断。
8. **弃置流程插 tmp_zone 阶段**:牌先入 tmp_zone → DISCARD_AFTER 触发离场效果(牌仍在 tmp_zone,效果子动作结算)→ 牌入弃牌堆 → DISCARD_SETTLE。因损伤弃置改走 `discard_card` 动作发时点。
9. **量产装可卖出已设置装备**:扩 sell 面板识别 effect_001。
10. **装备主动效果双入口**:无条件主动效果(机动头部抽牌、狙击右臂弃牌回动力)走装备面板"发动"按钮 + skill_bar;时点/条件触发效果走 permanent listener 自动触发。

## 二、架构现状与缺口(改造前)

| 缺口 | 现状 | 影响 |
|------|------|------|
| `set_equipment_action._register_equipment_effects` | 空 TODO | 装备效果从未注册到 TimingEngine,完全不生效 |
| `GeneratedActionEffects` | 只定义23张行动牌 | 无任何 `equipment_effect_*` |
| `CardSetService.set_equipment` | 用 `effect_registry.register_card` + `HOOK_EQUIPMENT_SET` | legacy,效果不走新体系 |
| attack record | 无 `effective_weapon_type` | 近战头部转换、狙击/近战条件判断无依据 |
| `damage_change` | 一次性 UI 放置,无逐点/汇总转移时点 | 联邦右臂、机动右臂损伤转移无法实现 |
| `discard_card_action` | 直接移入弃牌堆,无 tmp_zone/来源快照/reason | 离场诱发效果(联邦躯干/左臂、近战右腿)无法按 reason 过滤触发 |
| `MechSlotState` | 单一 modifier,无"按来源重算"/"损伤不影响护甲" | 派生值型、重甲头部效果无法表达 |
| `battle_message_log` | 监听 `effect_engine.hook_fired` | 与"弃 hook"约束冲突 |
| `sell_equipment_panel` | 只列手中+备用区 | 量产装已设置装备无法卖出 |
| `skill_bar` | 读 `effect.source.player_id` | 装备效果是共享 Resource,source 不携带具体牌实例,过滤失效 |

## 三、阶段 A:架构扩展(基础设施)

### A1. 新建 `scripts/generated_database/GeneratedEquipmentEffects.gd`
- `build_equipment_effects() -> Dictionary` 返回 `{effect_id: ActionEffect}`,定义全部31个 `equipment_effect_001~031`(42张牌共用)。
- 派生值 helper(被 MechState/MechSlotState 实时调用,避免硬编码牌名):
  - `compute_faction_armor_bonus(mech, slot_id)` — 联邦头部:其他区域联邦装备数
  - `compute_faction_power_bonus(mech, slot_id)` — 帝国头部:其他区域帝国装备数
  - `slot_damage_threshold_power_bonus(mech, slot_id)` — 重甲右臂/机动右腿(损伤≥1)、机动左腿(损伤≥2)
  - `card_has_damage_immune_armor(card)` — 重甲(effect_014)损伤不影响护甲
  - `is_equipment_active(card)` — 判断装备是否正面设置未禁用
  - `count_faction_equipment(mech, exclude_slot, substring)` — 同名装备计数
- **注意**:CHOOSE_ONE 的 options 必须是数组 `[{label, actions}]`(曾漏 `]` 闭合已修)。

### A2. `set_equipment_action._register_equipment_effects` 实现
- 从 `context.card_database.loader.get_effect_ids_map()` 取 `card.def.card_id` 的 effect_ids。
- 对每个 effect_id 查 `GeneratedEquipmentEffects`:
  - **LISTEN 模式**:按 `effect.listen_timing` 注册 permanent listener(ATTACK_BEFORE/PRE/AT/AFTER/SETTLE、USE_ACTION_AT、BASIC_MOVE_AFTER、DISCARD_AFTER、DAMAGE_REDIRECT_WINDOW 等)。
  - **DIRECT 模式**(机动头部、狙击右臂主动效果):用 `effect_id` 作虚拟时点注册(供 skill_bar/equipment_panel 扫描 + `_execute_effect_by_id` 触发)。
  - **派生值型**(002/008/014/016/021/023):不注册监听器(查询时实时算)。
- 注册时注入 `binding_context={card_instance_id, mech_id, player_id, card_def_id}`。
- `TimingEngine.register_permanent_listener` 扩支持 binding_context 参数 + 新增 `unregister_permanent_listeners_for_card`。
- `_make_binding_from_effect` 改签名接收 payload,优先从 `payload.binding_context` 取来源(装备 permanent listener 触发时,action 是被监听时点所属动作,source 是攻击方而非装备牌,必须从 binding_context 取)。
- `_step_discard_old` 调 `_unregister_equipment_effects`;`_step_place_equip` 补足:备用区 face_down、部件槽重算动力上限。

### A3. attack record 加 `effective_weapon_type` + `extra_range`
- `_step_select_weapon`:选定武器后 `result["effective_weapon_type"] = weapon_stats.weapon_kind`(默认=实体武器 kind);`_get_weapon_stats` 返回 weapon_kind。
- `_step_select_target`/`_step_check_hit`:有效范围 = `weapon_range + extra_range`(读修正后范围)。
- ActionService 新增特判:
  - `MODIFY_ATTACK_RANGE` — 写 `parent_action.record["extra_range"]`(支持 min_value 钳制),狙击头部远程范围+1。
  - `SET_ATTACK_EFFECTIVE_WEAPON_KIND` — 写 `parent_action.record["effective_weapon_type"]`,近战头部转换。

### A4. `discard_card_action` tmp_zone 流程 + 来源/原因快照
步骤重构为5步:
```
determine_cards(DISCARD_BEFORE) → move_to_tmp → fire_after(DISCARD_AFTER) → transfer_to_pile → settle(DISCARD_SETTLE)
```
- `_snapshot_discard_sources`:在移入 tmp_zone 前快照每张牌 `{card_id, from_mech_id, from_slot_id, from_zone, reason, def_id, card_kind}`,存入 `action.record["discard_snapshots"]`。
- `_step_move_to_tmp`:牌移入 tmp_zone(zone=temp_zone),从原区域/手牌移除,注销 AVAILABILITY/装备 permanent listener。
- DISCARD_AFTER 时点 payload 携带 discard_snapshots,离场效果监听此时点按 reason 过滤。
- `_step_transfer_to_pile`:牌从 tmp_zone 移入对应弃牌堆 + write_log(消息面板经 SessionLogger 显示,不走 legacy hook)。

### A5. 全量弃置入口统一走 `discard_card` 动作
所有装备弃置入口统一 `action_service.execute("discard_card", {card_ids, reason, executor, source})`,发出 DISCARD_BEFORE/AFTER/SETTLE 时点。**reason 常量统一**:

| 入口 | reason |
|------|--------|
| EquipmentBreakService.check_equipment_broken / GameActions._check_equipment_broken_after_damage | `damage_durability` |
| set_equipment._step_discard_old / EquipmentBreakService.replace_equipment | `equipment_replace` |
| TurnService 回合清理(超限行动牌/未设置装备) | `turn_cleanup` |
| CardSetService.sell_equipment(手中) | `sell` |
| CardSetService.sell_equipment(备用区/已设置区域) | `sell_set_equipment` |
| DISCARD_SELF_AND_REDUCE_ATTACK_MARKERS(联邦左腿) | `effect_self_discard` |

- `DeckService.discard_card` 转发到 discard_card 动作(保留同步签名,action_service 未就绪走 legacy 退路)。
- 防循环:离场效果子动作若再产生弃置,走同一动作链,靠 reason 区分;DISCARD_AFTER 监听器按 reason 过滤。
- legacy `GameActions.discard_card` 保留为内部实现(被动作 transfer 步骤调用)。

**A5b — CardSetService/EquipmentBreakService 去 legacy**:
- `CardSetService.set_equipment` 改为转发 `action_service.execute("set_equipment")`(装备效果走新体系注册到 TimingEngine,不再用 `effect_registry.register_card`/`HOOK_EQUIPMENT_SET`),保留 `_set_equipment_legacy` 退路。
- `EquipmentBreakService.replace_equipment` 同样转发 set_equipment 动作;移除 `_fire_hook`/`_EffectConst` import。

### A6. 损伤转移一次性汇总机制
- `TimingConst.DAMAGE_REDIRECT_WINDOW` 新增。
- `damage_change_action` 加 `_step_offer_redirect` 步(4步流程):`extract_info(DAMAGE_CHANGE_BEFORE) → offer_redirect(DAMAGE_REDIRECT_WINDOW) → set_damage(DAMAGE_CHANGE_AFTER) → settle(DAMAGE_CHANGE_SETTLE)`。
- `_step_extract_info`:暴露 `total_points = value` 供转移效果读取。
- `_step_set_damage`:若有 redirect_plan,先调 `place_damage_tokens_on_slot` 把转移点放到目标区域 + `_check_equipment_broken_after_damage`,剩余走原 UI 逐点/自动放置。
- **OFFER_DAMAGE_REDIRECT** 在 `TimingEngine._execute_actions` 拦截(同 CHOOSE_ONE 范式):
  - 玩家未选 + AI → `_ai_decide_redirect`(尽量转移保护装备)。
  - 玩家未选 → 挂起 `_pending_effect`(phase=redirect_select),emit `action_needs_input(redirect_select)`。
  - 已选 → `_write_redirect_plan` 写 parent_action.record["redirect_plan"]。
- `resume_pending_effect` 加 redirect_select phase 处理(取消=不转移,选了=写 plan)。
- ActionUIBridge `redirect_select` 分支;app_root 用 choice_panel 选转移点数档位(0/1/.../cap),`_on_choice_made` 解析 `__redirect_N__` 构造 redirect_plan 回填。

### A7. 派生值实时重算(MechState/MechSlotState)
- `MechState.get_armor`:聚合6部件 effective_armor + `compute_faction_armor_bonus(头部)`(联邦头部动态护甲)。
- `MechState.get_total_power`:聚合 + `compute_faction_power_bonus(头部)`(帝国头部) + 各 slot `slot_damage_threshold_power_bonus`(重甲右臂/机动右腿阈值1、机动左腿阈值2)。
- `MechSlotState.get_effective_armor`:检查 `card_has_damage_immune_armor`(effect_014 重甲),有则不减 region_damage_tokens(损伤不影响护甲)。
- `CardDatabase` 保存 loader 成员 + `get_effect_ids_map()`。
- **修**:GeneratedEquipmentEffects 对 RefCounted(MechSlotState/CardInstance)用属性访问,不能用 `.get(key, default)`(RefCounted.get 只接1参,2参报 "Expected 1 argument")。

### A8. 每回合1次(once_per_turn_key)
- `TimingEngine._execute_effect` 条件通过后检查 `_is_once_per_turn_used_up`(skip reason=once_per_turn_used_up)。
- 成功执行后(非挂起路径)`_mark_once_per_turn_used` +1。
- scope = `turn_number`(换回合自动失效,无需显式清零);card_instance_id 从 payload.binding_context 取。
- `_execute_effect_by_id` 精确匹配 `card_instance_id` + 注入 binding_context(双方同名装备区分)。
- 机动头部(effect_017)、狙击右臂(effect_024)用。

## 六、阶段 I:UI 接线

### I1. battle_message_log 从 hook 迁移到时点

## 八、关键架构事实(供后续维护)

- **ActionEngine** 驱动 steps,每步 timing_point 自动 fire,遇监听器暂停 waiting_timing,子动作完成后 continue_action 恢复;父子等待靠 pending_sub_action_ids + notify_sub_action_completed。
- **TimingEngine** permanent_listeners(装备/机师场上效果,统一存 `{effect, seq, binding_context}`)/temporary_listeners(行动牌,绑 action_id)/suppressed_effects(锁定封锁)。fire_timing 收集 listener 按priority排序执行,AVAILABILITY 走响应窗口,CHOOSE_ONE/optional弃牌/目标选择/redirect 有挂起态(_pending_effect + resume_pending_effect)。
- **装备 permanent listener 触发时**:action 是被监听时点所属动作(如 attack),其 source 是攻击方;装备效果的 condition/once_per_turn 必须**从 payload.binding_context 取**装备牌来源(card_instance_id/mech_id/player_id)。
- **DIRECT 装备主动效果**:注册时 timing=effect_id(虚拟时点),skill_bar/equipment_panel 扫描显示;触发走 effect_fire 动作 → `_execute_effect_by_id`(精确匹配 card_instance_id + 注入 binding_context)。
- **discard_card 动作 tmp_zone 流程**:快照→move_to_tmp(注销 listener)→DISCARD_AFTER(离场效果此时点触发,牌在tmp_zone)→transfer_to_pile→DISCARD_SETTLE。
- **attack record 字段**:attacker_id/target_id/weapon_id/weapon_might/weapon_range/effective_weapon_type/extra_might/extra_range/hit/responded/damage/markers/extra_markers/temporary_armor_bonus/damage_reduction。
- **RefCounted 注意**:MechSlotState/CardInstance/MechState 是 RefCounted,`.get(property)` 只接1参;需默认值时用 `"prop" in obj` + 属性访问,不能用 `.get(key, default)`。
