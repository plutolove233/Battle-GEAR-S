文档范围
• 覆盖“装备牌-N.xlsx”中全部 42 张部件装备牌，共 7 套、每套 6 个部位。
• 每张牌均写明效果类型、优先级、监听时点、对象、条件、记录字段、UI、动作输入、失败分支、持续时间、清理与多实例处理。

0. 文档定位与使用方式
目标：把简短牌面文字展开为可直接交给规则引擎、自动化测试或其他人工智能执行的确定性逻辑。
阅读顺序：先阅读第 1 章全局约定与第 2 章共用动作，再按牌号查阅第 4～10 章。每张牌的“完整执行步骤”是主流程，“失败、取消与跳过分支”是必须实现的异常流程。
覆盖范围：本文只展开表格中 N 品质部件装备牌；武器牌、R/SR/SSR 装备牌不在当前文件内。
名称规则：表格中“机甲名称”按 6 个部位向下继承，因此本文用“套装名·部位”作为唯一可读牌名，例如“联邦普装·右臂”。
1. 全局执行约定
1.1 动作、时点与暂停
任何效果实际执行前创建唯一效果动作 ID，并记录触发它的动作 ID、效果 ID、来源牌实例、所属机甲和参数快照。
时点只在发出的瞬间允许监听。监听成功后暂停原动作与后续步骤，按优先级从大到小执行；同优先级按登记先后。
插入效果和其调用的子动作全部结算后，才恢复原时点。恢复时必须读取最新状态，不能继续使用可能已过期的目标、位置、数值或牌区快照。
原动作允许被取消、中断或跳过步骤。任何分支都必须写入动作日志并清理临时锁、UI 与监听。
1.2 “可以/可”的统一 UI 规则
牌面出现“可以”或“可”时，默认是可选效果：条件满足后弹出确认窗口，至少有“发动/取消”。
取消不支付费用、不消耗每回合次数、不创建收益状态，也不应反复在同一个动作 ID 上再次弹出。
涉及选择牌、区域、数量或格子时，必须先显示合法选项；提交时再次校验，防止 UI 打开期间状态变化。
若没有合法选项，直接记录“条件不满足/无合法对象”，不弹空窗口。
1.3 装备牌生效状态
除离场触发外，装备效果仅在牌正面正式设置到合法区域后生效；设置装备牌时阶段尚不提供数值和效果，设置装备牌后才生效。
手牌、牌堆、弃牌堆、临时区和备用区背面牌默认不提供正面效果。
来源牌在效果动作成功创建后离场，已创建的效果动作仍按来源快照结算；尚未创建的监听立即注销。
每个装备实例独立记录状态、每回合次数、已处理动作 ID 和动态修正来源，禁止只按牌名共享状态。
1.4 护甲、动力与损伤的实现口径
装备牌面“动力”与持续效果中的“动力+1”等，默认修改机甲动力上限/总动力值；“回复 X 动力”修改当前常规动力且不超过上限。
“当前回合动力+X”使用独立临时动力池：立即可用、可以暂时超过上限、消耗时优先扣临时池，回合结束后清除未用部分。
“当前回合护甲+X”使用带来源的临时护甲状态，当前回合结束后移除；不同来源可叠加。
区域损伤留在区域，不跟随装备牌移动。每点损伤通常使区域护甲-1，并参与装备耐久判断；牌效明确替代时除外。
动力上限下降到低于当前常规动力时，默认把当前常规动力钳制到新上限；临时动力池单独保留到其到期。
1.5 “当前回合”“每回合”“每我方回合”
“当前回合”指效果触发时正在进行的玩家回合，不一定是装备所属玩家的回合。
“每回合1次”按每个玩家回合重置；“每我方回合1次”只在装备所属玩家的回合开始前重置。
取消选择不消耗次数；成本动作成功后，即使收益实际为0，默认也视为成功发动并消耗次数。
牌离场再回来不会在同一回合重置同一实例的已用标记。
1.6 攻击相关时点映射
“被指定为攻击目标时”映射到攻击时前：目标选择已完成，正式攻击时尚未发出。
“打出攻击牌/迎击牌时”映射到使用行动牌时：牌已进入临时区，主体效果尚未执行。
“攻击命中后”映射到攻击后：命中、伤害、损伤已计算，但生命变动和损伤变动尚未执行。
“发动攻击结算后”在当前动作体系中映射到攻击结算时点；监听效果结算后，攻击动作才清理。
1.7 默认优先级与冲突
表格没有给出优先级。本文默认普通装备效果优先级10；损伤位置替代、卖出合法性覆盖和近战类型转换等必须先处理的效果建议优先级20。
持续派生值不通过队列重复叠加，直接按来源重算。
同一数值存在多个修正时，依次应用并在最终阶段按规则做最低值/上限钳制。
若正式规则以后规定不同优先级，只替换优先级，不改变本文所列触发、记录与清理步骤。
1.8 弃置原因与原区域快照
装备牌进入弃置流程时必须记录原因：因损伤达到耐久、装备替换、出售、效果弃置、回合清理等。
凡是“从区域中弃置时”效果，弃置牌前必须记录原机甲与原区域；弃置牌后使用该快照。
只写“从区域中弃置时”的效果默认接受所有弃置原因；写明“因损伤而弃置”的效果只接受对应原因。
弃置后触发效果不能把已完成的弃置倒回，除非牌面明确写取消弃置。

• “帝国普装·躯干”的护甲-2是否到期：牌面未写持续时间，本文按无自动期限的独立护甲减少处理。

2. 共用动作模板（所有卡牌引用）
2.1 设置装备牌动作
1、提取装备牌 A、执行机甲、来源动作/效果；让玩家选择合法区域。
2、若区域有旧装备 B，执行弃置牌动作，原因=装备替换。
3、按 A 的耐久数值，从目标区域移除相同数量损伤；不足则移除全部。
4、发出设置装备牌前；把 A 放入区域但暂不提供数值；发出设置装备牌时。
5、A 正式设置并提供数值/效果；发出设置装备牌后；最后发出设置装备牌结算并清理。
2.2 弃置牌动作
1、记录可弃置牌、牌的当前持有者/区域、数量、执行方、来源和弃置原因。
2、需要玩家选择时弹出牌列表；隐藏牌对无权查看者显示未知，但执行者按其权限查看。
3、发出弃置牌前；把确定牌转移到对应弃牌堆；发出弃置牌后；最后弃置牌结算并清理。
2.3 数值修正动作
1、记录对象、类型（护甲/动力/威力/范围/金币）、数值、增加/减少/回复方式与来源。
2、发出数值修正前；应用修正与上限/最低值；发出数值修正后；数值修正结算后清理。
3、威力/范围修正对象是攻击动作；护甲/动力/金币对象是机甲。
2.4 损伤变动动作
1、记录机甲、可变动区域、数值、增加/减少、执行者、原因与来源。
2、发出损伤变动前；增加时逐点选择并设置，减少时逐点选择并移除；每点后立即检查装备耐久。
3、发出损伤变动后；损伤变动结算后清理。损伤位置替代效果在每点真正应用前介入。
2.5 获取牌动作
1、记录即将获取的牌、获取者对应关系、来源区域、获取原因与来源效果。
2、发出获取牌前；转移给获取者；发出获取牌后；获取牌结算后清理。
2.6 单次移动与基础移动
1、单次移动选择目标格并检查当前可用动力；确定路径后逐格执行基础移动。
2、基础移动前记录目标相邻格、机甲和可用动力；基础移动时支付地形动力；基础移动后更新位置。
3、每个成功基础移动计作移动1格；中断或不可执行时停止路径；单次移动结算后清理。

1、量产装·头部
序号	牌名	部位	品质	数量	金币
1	量产装·头部	头部	N	1	2
牌面数值：护甲 2；动力 0；耐久 2	牌面效果：此牌设置在区域中依然可以卖出。
基础设置与数值逻辑：本牌只能设置在头部装备牌区域。设置装备牌前按耐久 2 移除目标区域最多 2 点损伤；设置装备牌后提供护甲 2、动力上限 0。区域损伤达到耐久 2 时按通用规则弃置本牌，损伤保留在区域。
装备牌执行的效果 1——已设置装备牌仍可卖出
效果类型：常驻权限修改效果；不属于响应攻击效果。
优先级：建议优先级 20（作用于卖出操作的合法性检查，先于普通“已设置装备不可卖出”的否决）。
监听/发动时点：玩家在自己回合进行中点击本牌并发起“卖出装备牌操作”的合法性检查阶段；确认后依次进入弃置牌前、弃置牌后、数值修正前/后/结算。
对象与来源：对象为本装备牌实例（量产装·头部）及其所属机甲；收益接收者为该机甲/玩家。来源为本牌效果 1。
触发与可用条件：本牌必须正面正式设置在对应部位区域；当前必须是该牌所属玩家的回合进行中；本回合卖出装备牌数量未达到 2；本牌没有被其他效果锁定、临时移出或已经进入弃置流程。
动作记录字段：
效果动作 ID；监听到的卖出操作对应动作 ID；本装备牌实例 ID（量产装·头部）；本牌当前所属机甲 ID。
触发此效果的效果/动作及来源链：前序动作、前序效果、相关行动牌/装备牌、执行机甲或系统执行者。
触发瞬间的牌所在区域、是否为正面正式设置状态、区域损伤数、牌上耐久与牌面数值快照。
所有 UI 选择结果、取消标记、实际支付的费用、实际变更数值，以及被跳过或被中断的步骤。
卖出价格：本牌牌面金币 2；原设置区域；卖出前区域损伤数；本回合已卖出数量。
弃置原因固定记为“商店卖出已设置装备牌”，获取金币原因固定记为“卖出装备牌”。
完整执行步骤：
1、修改卖出操作的牌池生成逻辑：普通未设置装备牌照常列出，同时把本牌作为合法可卖对象列出，并明确标注“已设置，卖出后区域变为空”。
2、玩家点击本牌时，UI 显示：本牌完整信息、当前所在区域、区域现有损伤、卖出后失去的护甲 2 与动力 0 贡献、可获得金币 2，以及“确定卖出/取消”。
3、选择取消：关闭窗口，不创建卖出动作，不消耗每回合卖出次数，不改变任何状态。
4、选择确定：创建卖出操作 A，记录本牌原区域与数值快照；再次检查本牌仍在原区域、卖出次数仍合法，防止 UI 打开期间被其他效果改变。
5、执行弃置牌动作 B——输入：将要可以弃置的牌信息=本牌；弃置数量=1；执行方=本牌所属机甲/玩家；来源=卖出操作 A、本牌效果 1、本牌；弃置原因=商店卖出已设置装备牌。
6、B 的弃置牌前时点必须保留原区域字段；把本牌转移到装备弃牌堆后，区域变为空，本牌对护甲、动力、耐久判断和其他效果的贡献立即失效。区域上的损伤不随装备牌移动，除非另有牌效明确移除。
7、仅当 B 成功结算后，执行数值修正动作 C——对象=本牌所属机甲；类型=金币；数值=2；修正方式=增加；来源=卖出操作 A、本牌效果 1、本牌。
8、C 成功结算后，本回合卖出装备牌计数 +1；刷新机甲数值、区域 UI、商店 UI 与弃牌堆信息；卖出操作 A 结算并清理。
失败、取消与跳过分支：
若确认时本牌已经离开原区域、被翻面、被替换或卖出次数已满，则中断 A，并提示“状态已变化，无法卖出”。
若弃置牌动作被无效、替代或中断，则不获得金币，也不增加卖出次数。
若弃置本牌触发其他“从区域中弃置时”效果，先按同一时点优先级结算这些效果；金币结算仍以 B 是否最终成功为条件。
机甲因卖出后失去动力上限而出现当前动力高于新上限时，按全局动力上限规则处理；不得凭空回复或重复扣除动力。
持续时间与清理：本效果本身为常驻权限；只要本牌正面正式设置就持续有效。卖出成功后，因来源牌离开区域，本常驻权限立即注销。
多效果/多实例处理：若未来存在多张同名牌，每个实例只授权卖出自身；卖出次数仍按玩家的全局每回合上限统一计算，不能因多个实例提高上限。

2、玩家点击本牌时，UI 显示：本牌完整信息、当前所在区域、区域现有损伤、卖出后失去的护甲 3 与动力 2 贡献、可获得金币 4，以及“确定卖出/取消”。
3、选择取消：关闭窗口，不创建卖出动作，不消耗每回合卖出次数，不改变任何状态。
4、选择确定：创建卖出操作 A，记录本牌原区域与数值快照；再次检查本牌仍在原区域、卖出次数仍合法，防止 UI 打开期间被其他效果改变。
5、执行弃置牌动作 B——输入：将要可以弃置的牌信息=本牌；弃置数量=1；执行方=本牌所属机甲/玩家；来源=卖出操作 A、本牌效果 1、本牌；弃置原因=商店卖出已设置装备牌。
6、B 的弃置牌前时点必须保留原区域字段；把本牌转移到装备弃牌堆后，区域变为空，本牌对护甲、动力、耐久判断和其他效果的贡献立即失效。区域上的损伤不随装备牌移动，除非另有牌效明确移除。
7、仅当 B 成功结算后，执行数值修正动作 C——对象=本牌所属机甲；类型=金币；数值=4；修正方式=增加；来源=卖出操作 A、本牌效果 1、本牌。
8、C 成功结算后，本回合卖出装备牌计数 +1；刷新机甲数值、区域 UI、商店 UI 与弃牌堆信息；卖出操作 A 结算并清理。
失败、取消与跳过分支：
若确认时本牌已经离开原区域、被翻面、被替换或卖出次数已满，则中断 A，并提示“状态已变化，无法卖出”。
若弃置牌动作被无效、替代或中断，则不获得金币，也不增加卖出次数。
若弃置本牌触发其他“从区域中弃置时”效果，先按同一时点优先级结算这些效果；金币结算仍以 B 是否最终成功为条件。
机甲因卖出后失去动力上限而出现当前动力高于新上限时，按全局动力上限规则处理；不得凭空回复或重复扣除动力。
持续时间与清理：本效果本身为常驻权限；只要本牌正面正式设置就持续有效。卖出成功后，因来源牌离开区域，本常驻权限立即注销。
多效果/多实例处理：若未来存在多张同名牌，每个实例只授权卖出自身；卖出次数仍按玩家的全局每回合上限统一计算，不能因多个实例提高上限。

11. 附录：建议的数据结构与测试用例
A. 装备效果实例最小数据结构
cardInstanceId、cardDefinitionId、ownerMechId、regionId、faceUp、formallySet、effectEnabled。
sourceEffectId、priority、registeredTiming、handledActionIds、createdActionIds。
turnUsage：resetScope（eachTurn/ownerTurn）、lastResetTurnId、used。
dynamicModifier：type、value、active、targetId、expiresAt、sourceInstanceId。
triggerSnapshot：originalRegionId、discardReason、attackId、weaponId、targetIds、beforeValues、UIChoice。
B. 每张牌至少需要的自动化测试
1、正常发动：条件满足、玩家发动、所有子动作与时点顺序正确。
2、取消：在每个可取消窗口取消，确认无费用、无次数、无残留状态。
3、条件边界：数值刚好等于阈值、牌堆为空、手牌刚好够成本、范围最低为1、损伤刚好达到耐久。
4、状态竞争：UI 打开后目标/牌/区域变化，提交时必须二次校验。
5、多实例：两张同类效果同时监听，优先级、先来后到、叠加与去重正确。
6、来源离场：效果已入队后来源离场仍结算；未入队监听应注销。
7、中断与无效：子动作被中断时收益是否不产生、已支付成本是否按本文规则保留。
8、清理：回合结束、攻击结算、牌离场后所有临时状态、监听、缓存与 UI 锁均被移除。
C. 规则变更时的维护顺序
1、先更新第 1 章全局约定，再更新受影响的共用动作模板。
2、逐张检查卡牌的时点、优先级、成本、持续时间与清理。
3、修改自动化测试的预期动作序列，不只修改最终数值。
4、保留旧版本的规则版本号与迁移说明，避免旧对局状态无法恢复。
