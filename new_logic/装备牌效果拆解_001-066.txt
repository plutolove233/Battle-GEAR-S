[装备牌 001] 量产装·头部  （部位:头部  护甲:2 动力:0 耐久:2 金币:2）
═══════════════════════════════════════════════════════════
效果文本：此牌设置在区域中依然可以卖出。
effect_ids：["equipment_effect_001"]

──────────── 效果拆解（equipment_effect_001）────────────
优先级：10
模式：权限型
植入：权限型，不注册监听器。装备设置在部件区域后，sell_equipment_panel / shop sell 流程读取牌定义中的 effect_ids，识别本权限。
权限型：不写 conditions / target_rules / costs / actions，不注册 timing listener。

依赖/限次：无；卖出次数仍受玩家每回合最多卖出2张装备牌的全局规则限制。
值解析/公式：识别来源：$binding_context.card_instance_id / card_def_id；卖出价取该牌金币字段，不因已设置而改变。
执行顺序：卖出确认后必须走标准 discard_card(reason=&"sell_set_equipment")，再 GAIN_GOLD；不能直接清槽，否则离场诱发与监听器注销会漏掉。
人类 UI：装备详情/商店卖出面板在该牌已设置时仍显示“卖出”按钮；确认窗显示卖价与将清空的部位。

──────────── 实现预告 ────────────
- 复用：equipment_effect_001（既有权限型）。
- 权限检查：sell 面板允许 zone==equipped 且牌含本 effect_id；仍检查当前回合卖出计数、牌所有权与动作空闲。
- JSON effect_ids：001～006 均为 ["equipment_effect_001"]；无需新增 ActionEffect。

──────────── 顺序与坑 ────────────
- 卖出已设置牌会让该区域保留原损伤，除非其他离场效果另行移除；规则仅规定设置新牌时移除新牌耐久数量损伤。
- 卖出原因应与普通未设置装备卖出区分为 sell_set_equipment，便于离场效果按 reason 过滤。

──────────── 测试场景 ────────────
场景a：已设置装备正常卖出
  前置：P装备量产装·头部于头部；本回合卖出计数0；牌面金币=2；涉及选择的玩家均is_human=true。
  操作：打开装备详情→点击卖出→确认。
  断言：头部.equipped_card==null；卡实例zone=="equipment_discard"；discard.reason==&"sell_set_equipment"；P.gold增加2；本回合卖出计数+1。
场景b：卖出确认窗取消
  前置：量产装·头部已设置于头部；涉及选择的玩家均is_human=true。
  操作：点击卖出→取消。
  断言：牌仍在头部；金币不变；无discard/GAIN_GOLD动作。
场景c：全局卖出次数已满
  前置：P本回合已经卖出2张装备牌；涉及选择的玩家均is_human=true。
  操作：查看量产装·头部。
  断言：卖出按钮禁用或权限检查失败；牌与金币不变。

歧义点：
[歧义1] 已设置牌卖价是否仍取牌面金币全额。智能体选择：取牌面金币全额（理由：文本只扩展可卖权限，未修改卖价；商店规则的卖出价即牌面金币）。候选：按损伤/耐久折价。▶ 回答：____________________

    "op": &"PAYLOAD_STAT_METHOD_IS",
    "method": &"spend"
  },
  {  # 累计消耗达到8
    "op": &"POWER_SPENT_THIS_TURN_ABOVE",
    "threshold": 8
  },
]

目标规则 target_rules：
[
  {  # 回复本牌机甲
    "rule": &"NO_TARGET"
  },
]

成本 costs：
[]

动作 actions（GDScript 字面量；内层 actions 已展开）：
[
  {  # 达标后可取消，确认回复
    "type": &"CHOOSE_ONE",  # 弹出可取消/不可取消选择窗；窗口完成前父动作挂起
    "params": {
      "optional": true,
      "options": [
        {
          "label": "回复2动力",
          "actions": [
            {
              "type": &"RESTORE_POWER",  # 回复动力，不超过当前总动力上限
              "params": {
                "amount": 2,
                "target_id": "$binding_context.mech_id"
              }
            }
          ]
        }
      ]
    }
  },
]

依赖/限次：无（requires_effect=&""）；once_per_turn_key=&"equipment_effect_044_$binding_context.card_instance_id"，once_per_turn_max=1；成功发动后消耗。
值解析/公式：$payload.value_after；mech.turn_counters.power_spent。
执行顺序：第8点累计消耗的stat_modify settle→弹窗→回复→返回父动作。
人类 UI：达标弹“回复2动力/取消”。

──────────── 实现预告 ────────────
- 需新增 equipment_effect_044，仿帝国普装腿effect_012/013；复用POWER_SPENT_THIS_TURN_ABOVE。
- 同时需SELF_MECH_IS_STAT_TARGET/PAYLOAD_STAT_*新op（可与effect_017共用）。

──────────── 顺序与坑 ────────────
- 只累计实际扣除的动力；试图消耗但因不足失败的值不计。
- 回复的动力若之后再次消耗，不减少累计已消耗计数。

──────────── 测试场景 ────────────
场景a：累计消耗第8动力后回复2
  前置：M装备帝国的赤枭·右腿；power_spent_this_turn=7；当前动力低于上限；涉及选择的玩家均is_human=true。
  操作：再实际消耗1动力→STAT_MOD_SETTLE→确认。
  断言：power_spent_this_turn==8；current_power回复2且不超上限；once=1。
场景b：达标取消
  前置：同a；涉及选择的玩家均is_human=true。
  操作：取消。
  断言：不回复且once未占用；之后再消耗动力可再次提示。
场景c：非动力消耗或已用
  前置：分支1为动力回复/增加；分支2本回合已成功发动；涉及选择的玩家均is_human=true。
  操作：进入STAT_MOD_SETTLE。
  断言：不触发。
