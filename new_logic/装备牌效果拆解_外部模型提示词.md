## 一、游戏运行逻辑：Action Engine 效果体系

### 1.1 一个效果（ActionEffect）的组成

每张牌 = 1~N 个 effect。每个 effect 由以下部分构成：

| 部分 | 字段 | 说明 |
|------|------|------|
| 标识 | `effect_id` / `display_name` / `description` | effect_id 形如 `equipment_effect_NNN` |
| 模式 | `mode` | `DIRECT`（打出/发动立即执行）/ `LISTEN`（监听某动作某时点）/ `AVAILABILITY`（响应窗口可选牌） |
| 优先级 | `priority` | int，**大先执行**。常规=10；最低=-1；20/30 用于顺序保证 |
| 监听 | `listen_timing` + `listen_action_type` | LISTEN 专有：监听哪个动作类型的哪个时点 |
| 条件 | `set_conditions([{op,params}])` | 全部满足才触发 |
| 目标规则 | `set_target_rules([{rule}])` | 目标合法性 |
| 成本 | `set_costs([{cost_type,count,optional}])` | 触发前支付；`optional:true` 即「可以」 |
| 动作 | `set_actions([{type,params}])` | 按序执行的内容 |
| 依赖 | `requires_effect` | 必须先执行完此 effect_id 才触发 |
| 每回合1次 | `once_per_turn_key`+`once_per_turn_max` | 每回合限次 |
| 手牌永久 | `permanent_while_in_hand` | 手牌期间作永久监听器（掩护/推进） |
| 可用条件 | `availability_condition`+`availability_priority` | AVAILABILITY 专有 |

**值解析**：`$payload.xxx` 读触发动作的 record；`$binding_context.xxx` 读注册时注入的来源（装备牌：`card_instance_id`/`mech_id`/`player_id`/`card_def_id`）。

### 1.2 执行顺序

- 同一时点按 `priority` **降序**执行；同级**行动牌按注册序（先来后到）**，**装备牌按座次**（turn_order 序号，tier/seat 低 1 级 tiebreak）。
- `ATTACK_AT` 开响应窗口：AVAILABILITY 牌成可选；窗口关闭后才跑 regular 监听器。
- 「可以…」=`CHOOSE_ONE`+`optional:true` 或 optional 成本；多选=`CHOOSE_MANY_CARDS`；「每回合1次」=`once_per_turn_key`。
- 需玩家输入的动作（选目标/选牌/移动/弹窗）挂起父动作，串行机制保证多输入子动作依次执行。
- 状态效果（聚能/联合/锁定/折扣）有独立 LISTEN 监听器，施加时注册、移除时注销。

### 1.3 装备牌三种植入模式（行动牌只有 DIRECT/LISTEN/AVAILABILITY，装备牌多出「派生值」）

| 模式 | 触发方式 | 拆解首句点明 |
|------|---------|-------------|
| **永久监听 LISTEN** | set_equipment 设置到区域后注册永久监听器（binding_context 注入来源），弃置/替换时注销 | 「设置到\<区域>后由 set_equipment 注册为永久监听器，监听\<动作类型>的\<时点>」 |
| **派生值实时重算** | **不注册监听器**，在 MechState.get_armor/get_total_power、MechSlotState.get_effective_armor 查询时调 helper 重算 | 「派生值型，不注册监听器。查询时实时重算：\<规则>」 |
| **DIRECT 主动** | 装备面板「发动」按钮/skill_bar 触发 `effect_fire` 动作 | 「DIRECT，由装备面板发动按钮/skill_bar 触发」 |
| **AVAILABILITY 响应** | 响应窗口（ATTACK_AT）可选 | 「装备牌的可用条件（响应攻击）：优先级 N」 |
| **权限型** | 不注册监听器，由特定面板识别（如量产装可卖出） | 「权限型，由 \<面板> 识别」 |

## 二、既有件清单（优先复用，勿重复造）

拆解时**机制相同的优先复用**下列既有件；仅当确实无匹配时才提「需新增」，并在实现预告里写明命名（仿下述风格）+ 仿哪个既有范式。

### 2.1 时点（TimingConst）

- **效果模式**：`MODE_DIRECT` / `MODE_LISTEN` / `MODE_AVAILABILITY`
- **可用条件类型**：`AVAIL_RESPOND_ATTACK`（响应攻击）、`AVAIL_ALLY_IN_RANGE_TARGETED`（范围内友方被攻击）
- **回合**：`ROUND_START`、`TURN_BEFORE_START`、`TURN_START`（回复动力）、`TURN_AFTER_START`（抽牌+金币后）、`TURN_BEFORE_END`、`TURN_END`、`TURN_AFTER_END`
- **攻击**：`ATTACK_BEFORE`（选武器后）、`ATTACK_PRE`（选目标后，响应窗口前）、`ATTACK_AT`（发动攻击，响应窗口）、`ATTACK_AFTER`（伤害计算后）、`ATTACK_SETTLE`（结算清理）
- **使用行动牌**：`USE_ACTION_BEFORE`、`USE_ACTION_AT`（牌进临时区后）、`USE_ACTION_AFTER`、`USE_ACTION_SETTLE`
- **数值修正**：`STAT_MOD_BEFORE/AFTER/SETTLE`
- **移动**：`BASIC_MOVE_BEFORE/AT/AFTER/SETTLE`、`SINGLE_MOVE_SETTLE`
- **设置装备**：`SET_EQUIP_BEFORE/AT/AFTER/SETTLE`
- **获取牌**：`GAIN_CARD_BEFORE/AFTER/SETTLE`
- **弃置牌**：`DISCARD_BEFORE`、`DISCARD_AFTER`（牌在 tmp_zone，离场诱发在此触发）、`DISCARD_SETTLE`
- **效果发动**：`EFFECT_FIRE_BEFORE/AFTER/SETTLE`
- **生命变动**：`HP_CHANGE_BEFORE/AFTER/SETTLE`
- **损伤变动**：`DAMAGE_CHANGE_BEFORE/AFTER/SETTLE`
- **损伤转移窗口**：`DAMAGE_REDIRECT_WINDOW`（damage_change 放损伤前 fire，转移效果监听并弹汇总窗）
- **展示牌**：`SHOW_CARD_BEFORE/AFTER/SETTLE`
- `VICTORY_REACHED`

**损伤转移**：`REDIRECT_TARGET_HAS_ANY_EQUIP`（目标有任意装备）、`REDIRECT_TARGET_HAS_FACTION_EQUIP`(faction_substring)（目标有名含子串装备）、`REDIRECT_HAS_DESTROYABLE_EQUIP`（有装备即将因损伤弃置）

## 三、拆解输出格式（开发就绪·详细结构）

> 目标：让写代码的工程师能**直接照此写 ActionEffect + 测试**，无需二次拆解。每个效果必须给出可复制进代码的 GDScript 字面量（conditions/target_rules/costs/actions），外加自然语言解释、实现预告、顺序与坑、详细测试场景。

每张牌一节，结构如下（用 part_032 狙击装·躯干 作完整范本，细节均已核实）：

```
═══════════════════════════════════════════════════════════
[装备牌 032] 狙击装·躯干  （部位:躯干  护甲:3 动力:1 耐久:2 金币:3）
```

### 格式要点（必须遵守）

1. **conditions / target_rules / costs / actions 必须给 GDScript 字面量**（StringName 用 `&"..."`），工程师可直接粘进 `set_conditions([...])` / `set_actions([...])`。`CHOOSE_ONE`/`CHOOSE_MANY_CARDS` 的 `options` 逐层展开到内层 actions。
2. **每个动作附行内注释**（`#`）说明它改什么字段/调什么，附自然语言「输入：发动方/触发来源/目标/数量/原因」。
3. **执行顺序**：多动作时写清先后与挂起点（哪个子动作会把父动作置 waiting_effect_action）。
4. **派生值型**：不写 conditions/actions，改写「helper 名 + 接入点（MechState.get_armor / get_total_power / MechSlotState.get_effective_armor）+ 公式（统计口径：哪些槽、名称含什么、是否含备用区、阈值或逐点）」。
5. **DIRECT 主动**：写「触发入口（装备面板发动按钮/skill_bar -> effect_fire）+ conditions（IS_OWNER_MAIN_PHASE 等）+ costs + actions + once_per_turn_key」。
6. **AVAILABILITY 响应**：写「availability_condition + availability_priority + 触发时点（ATTACK_AT）+ conditions + actions」。
7. **复合效果**（一张牌多个不相关效果，如轰雷头部=远程范围+2 + 损伤免疫阈值）：**拆多个 effect_id**，每个独立一节「效果拆解」，JSON effect_ids 列全。
8. **需新增件**：在「实现预告」逐条列【名称/语义/参数/仿哪个既有/登记点】。能复用就复用，别造重复件。
9. **测试场景**：每张牌至少给「正常发动 / 取消 / 条件不满足」3 类；复合、易错或新机制牌再加边界场景（如与其他效果共存、离场、重复触发、递归）。每个场景写清：前置（谁装什么于哪槽、敌方状态、回合/动力/手牌、is_human）、操作（按步：谁做什么 -> 哪个时点触发 -> 弹什么窗 -> 选什么 -> 继续）、断言（具体到字段名与期望值，如 `attack.record["extra_might"]==-4`、`zone=="equipment_discard"`、`slot.equipped_card==null`、监听器已注销等）。
10. **歧义点**：凡有多种读法处必留 `[歧义N] ... ▶ 回答：____________________` 行。

## 四、歧义回答行格式

凡有效果文本存在多种读法处，**必须**留回答行（已并入上面每张牌的「歧义点」）。格式：

`[歧义N] <歧义点描述> 智能体选择：<你选的读法>（理由：…）。候选：<其他读法简述>。▶ 回答：____________________`

▶ 回答行留空 = 人类同意你的选择；不同意则人类在此行改写裁定。**不臆断**。典型歧义：「可以」是否可选、触发时点选 ATTACK_PRE/ATTACK_AT、目标范围、是否消耗攻击次数、动力加成是上限还是当前值、损伤统计范围、「打出/使用」措辞差异、复合效果是否拆多 effect_id、光环是否影响敌方机甲、递归发动是否限次、转移/减损伤的「最多」如何选等。

## 六、硬约束

1. **唯一权威**：提供的 4 份文档（规则书/行动牌效果与逻辑/各动作生命周期与时点/装备牌部件全部信息）。冲突以文档为准，不以本提示词的既有件清单为准。
2. **全面弃 hook**：只用 Action+时点体系，不碰旧 hook。消息层走时点+日志。
3. **先 PvP 人类玩家 + UI**：逻辑/UI 要对任意数量人类玩家可复用；AI 逻辑暂不管。
4. **逐效果独立实现**：同型效果机制不同就拆独立 effect_id，接受少量重复；但**机制相同优先复用既有 op/原子动作/effect_id**，新建仅当确实无匹配。
5. **数据层**：effect_ids 数组手工维护，不重新生成。
6. **不臆断**：歧义必留回答行，不私自裁定。
7. **GDScript 字面量精确**：conditions/actions 等给的字面量必须能直接粘进代码（StringName 用 `&"..."`、字典/数组语法正确、嵌套层级清晰）。

## 七、关键坑（拆解时须正确处理）

- **优先级错开保证顺序**：同一时点同优先级按注册序/座次跑。需严格先后时用 priority 错开（如反击 effect2=20 先于闪击 effect2=10；预判 effect2=30 先于掩护 effect1=10）。近战头部类型转换 priority 20 须先于近战威力+2 的 priority 10。
- **触发时点选择**：「被指定为攻击目标时」=ATTACK_PRE（选目标后、响应窗口前，最早可判定 target_id）；「被攻击命中时」=ATTACK_AFTER（伤害计算后）；「攻击结算后」=ATTACK_SETTLE；「打出/使用攻击牌时」=USE_ACTION_AT；「移动后」=BASIC_MOVE_AFTER。
- **武器类型判定**：读 `attack.record.effective_weapon_type`（近战头部转换后的有效类型），条件 op 用 `ATTACK_EFFECTIVE_WEAPON_KIND`/`ATTACK_EFFECTIVE_WEAPON_KIND_NOT`（已内置 effective 优先退回 weapon_kind）。
- **离场诱发**：监听 `DISCARD_AFTER`（牌在 tmp_zone），条件 `DISCARD_IS_SELF_FROM_SLOT` + 按需 `DISCARD_REASON_IS`；弃置全量走 discard_card 动作，按 reason 过滤防循环。
- **损伤转移**：监听 `DAMAGE_REDIRECT_WINDOW`，一次性汇总窗（非逐点），写 redirect_plan。
- **派生值型不注册监听器**：查询点实时重算（MechState.get_armor/get_total_power、MechSlotState.get_effective_armor(mech)）。
- **状态挂 A 时点、fire 在 B 时点时，target 须用 `$binding_context.xxx`** 而非 `$payload.xxx`。
- **复合效果**：一张牌多个不相关效果（如轰雷装头部=远程范围+2 + 损伤免疫阈值）应拆多个 effect_id，在拆解里分别成节。
