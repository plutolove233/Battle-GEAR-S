========================================================================
适用范围与共同约定
========================================================================
1. 本文只使用新 Action + Timing 体系；不调用旧 hook / legacy CardEffect。
2. 机师设置到 slot_id=&"pilot" 后，LISTEN / AVAILABILITY / DIRECT 均按 card_instance_id 注册；更换机师时先注销旧实例的全部 permanent listener，再注册新实例。
3. “可以/可”均提供取消路径；除非技能已明确支付成本并进入不可逆后续，否则取消不消耗限次。
4. “每回合”按当前活动玩家的回合计数并在每个 TURN_BEFORE_START 重置；“我方回合”只在机师拥有者回合内可触发。
5. 所有由“立即使用”引出的攻击均为 passive=true，不消耗回合攻击数；“视为”仍是已打出的实体行动牌，仅替换其效果链。
6. 六角格范围统一使用 _HexGrid.distance；不使用武器 BFS 攻击范围替代文字中的“X格范围”。
7. 四份权威文档未包含现有 pilot JSON / 旧 GeneratedPilotEffects.gd 的 effect_ids 数组。本批按既有命名规则给出可落码的 pilot_XXX_effect_YY（必要时带 a/b）并列为“本拆解 effect_ids”；合入时必须与项目当前 JSON 手工核对，若旧数组名称不同，只做 ID 映射，不改变本文逻辑。
8. GDScript 字面量中的动态值（如 "$payload.target_id"）由 ActionEngine 的值解析器在执行时替换。

效果文本：每回合1次，我方使用行动牌时，可以使该效果生效2次（2次独立结算，第1次效果结算后，若条件满足则第2次效果立即生效）。

description：每回合1次，我方使用行动牌并完成第1次效果结算后，可将该牌当前有效效果链以新的子动作ID再执行1次。
优先级：10
模式：LISTEN

逐行动解释：
- CHOOSE_ONE：由阿克罗姆拥有者决定是否发动；窗口完成前，原 use_action_card 的 USE_ACTION_AFTER 时点及后续监听器暂停。
- REPEAT_USED_ACTION_EFFECT_CHAIN：
  输入：第1次 use_action_card record、该实体牌实例、其经过“视为”后的当前有效 effect 列表；
  输出：一套新的 effect_fire / attack / move / gain 等子动作ID；
  目标与选项：全部重新选择，不能复用第1次输入；
  攻击计数：第2次是机师效果引出的被动攻击，passive=true，不再扣回合攻击数；
  来源追踪：保留 original_card_instance_id，同时标记 repeated_by_effect_id=&"pilot_001_effect_01"、repeat_index=2；
  清理：实体牌仍只由原 use_action_card 在 USE_ACTION_SETTLE 时弃置1次。

执行顺序：
1. 原行动牌第1次效果链完成；
2. 发出 USE_ACTION_AFTER；
3. pilot_001_effect_01 弹可选窗并挂起原 use_action_card；
4. 确认后克隆当前有效效果链；
5. 第2套效果链独立选目标、独立结算；
6. 若第2次执行前置条件已不满足，则该分支立即失败，不回滚第1次，也不重新弹其他选择；
7. 返回原 USE_ACTION_AFTER，继续后续监听器，最终原实体牌只弃置1次。

值解析：
- $payload.action_id：原 use_action_card 动作ID。
- $payload.card_instance_id：实体行动牌实例。
- $payload.effective_effect_ids：经“视为”等替换后的最终效果链。
- $binding_context.mech_id/player_id：阿克罗姆拥有者。

人类 UI：
- 机师牌旁按钮1：被动置灰“本回合双重生效 0/1 或 1/1”。
- 第1次效果链完成后弹窗：“是否使【牌名】的效果再生效1次？”。
- 悬停显示：本回合剩余次数、当前重复来源牌、若第2次已不具备合法目标则显示“条件不满足，无法重复”。

──────────── 实现预告 ────────────
- 需新增原子/复杂动作【REPEAT_USED_ACTION_EFFECT_CHAIN】
  语义：复制 use_action_card record 中最终有效的 effect 链，以新动作ID再执行，不再次移动/弃置实体牌，不再次发 USE_ACTION_*。
  参数：source_use_action_id、source_card_instance_id、repeat_index、repeat_depth、recheck_all_conditions、reuse_previous_choices、attack_is_passive。
  仿照：EXECUTE_EFFECT_FIRE + 行动牌 effect 路由器；攻击分支仿 EXECUTE_ATTACK(passive=true)。
  登记点：ActionService.gd、TimingEngine._execute_actions、ActionRecordFactory、行动牌 effect 路由器。
- 需新增条件 op：
  1. USED_CARD_EXECUTOR_IS_SELF（仿 USED_CARD_OWNER_IS_SELF，但读取use_action.executor_mech_id）；
  2. PAYLOAD_IS_PHYSICAL_ACTION_CARD；
  3. PAYLOAD_EFFECT_CHAIN_COMPLETED；
  4. PAYLOAD_REPEAT_DEPTH_BELOW(max_depth)。
  登记点：ConditionChecker.gd。
- 需扩展 use_action_card record：effective_effect_ids、effect_chain_completed、repeat_depth、original_card_instance_id。
- 需重写旧 pilot_001 占位为上述新 ActionEffect；不得用 CUSTOM_EFFECT_CHECK_TEXT。

──────────── 顺序与坑 ────────────
- 必须复制“最终有效效果链”，而不是牌面原始效果；若该牌已被“视为强袭”，第2次也执行强袭链。
- 第2次不能发出新的 USE_ACTION_*，否则会错误触发“使用行动牌时”类效果并可能递归触发阿克罗姆。
- 攻击牌原本只因实体牌使用扣1次回合攻击数；第2次攻击为 passive=true。
- 强袭、闪击、反击等绑定攻击ID的后续效果必须绑定到第2次新建的攻击ID，不能继续监听第1次攻击。
- 维修、联合等需要目标/分支输入的牌，第2次重新选；第1次目标死亡或条件变化时必须重新校验。
- 若第1次牌效果被取消且没有真正生效，effect_chain_completed=false，不弹技能窗。
- 若玩家在阿克罗姆窗取消，once_per_turn 不消耗；确认后即占用次数，即使第2次因瞬时条件变化失败也不返还。

──────────── 测试场景 ────────────
场景a：正常发动——维修独立结算2次
  前置：P1设置阿克罗姆；P1主阶段持有真实“维修”；M1与相邻M2均为非满状态；本回合技能未用；is_human=true。
  操作：
  1. P1确认使用维修，USE_ACTION_AT执行第1次维修，选择M1回复4生命；
  2. 第1次维修完成，USE_ACTION_AFTER触发技能窗；
  3. 选择“再生效1次”，第2次重新选择M2移除2损伤。
  断言：
  - 只存在1个 use_action_card 动作；
  - 有2组独立维修 effect_fire/生命或损伤动作ID；
  - M1.hp按回复规则增加4，M2.damage_tokens减少2；
  - 维修实体牌最终仅进入行动弃牌堆1次；
  - once_per_turn_state["pilot_001_effect_01@<pilot_instance>"]==1。

场景b：攻击牌重复——只消耗1次回合攻击数
  前置：P1设置阿克罗姆；P1回合攻击数剩余1；持有进攻；两台敌机或同一敌机均有合法攻击范围；技能未用；is_human=true。
  操作：使用进攻完成第1次攻击；确认重复；第2次重新选武器/目标并完成攻击。
  断言：
  - 第1次 attack.passive==false；第2次 attack.passive==true；
  - P1.current_attack_count 只减少1；
  - 两次 attack.action_id 不同；
  - 两次伤害/损伤分别计算并记录；
  - 不产生第二个 USE_ACTION_AT。

场景c：取消发动
  前置：同场景a。
  操作：第1次维修完成后，在阿克罗姆窗选择取消。
  断言：
  - 无 REPEAT_USED_ACTION_EFFECT_CHAIN 子动作；
  - 技能次数仍为0；
  - 原行动牌正常进入弃牌堆；
  - 第1次维修结果保留。

场景d：第2次条件不满足
  前置：P1使用维修；场上仅M1受损，且第1次维修使其达到满血且0损伤；技能未用；is_human=true。
  操作：第1次完成后确认重复。
  断言：
  - 重复路由重新校验维修可用条件失败；
  - 不弹目标窗、不产生回复/移除动作；
  - 第1次结果不回滚；
  - 确认后技能次数记为1。

场景e：阻止递归
  前置：任意可正常重复的辅助牌；is_human=true。
  操作：确认阿克罗姆重复。
  断言：
  - 第2次效果链 repeat_depth==1；
  - 第2次结束时不会再次触发 pilot_001_effect_01；
  - 一次实体牌使用最多产生2次效果链。

歧义点：
[歧义1] 重复攻击是否再次消耗回合攻击数。智能体选择：不再次消耗（理由：只有一次实体攻击牌使用；第2次由机师效果引出，符合“立即使用/效果引出的攻击为被动攻击”口径）。候选：两次均算主动攻击并各扣1次。▶ 回答：_____智能体选择正确_______________
[歧义2] 第2次是否复用第1次目标/选择。智能体选择：全部重新选择并重新校验（理由：“2次独立结算”）。候选：完全复制第1次目标与选项。▶ 回答：__智能体选择正确__________________
[歧义3] “该效果”是只重复行动牌的主效果，还是重复牌的完整多 effect 链。智能体选择：重复经视为后完整有效效果链（理由：强袭/闪击等牌的后续监听也是该行动牌效果的一部分）。候选：只重复 effect1。▶ 回答：_智能体选择正确___________________
[歧义4] 玩家确认重复后，第2次瞬时条件失败是否返还每回合次数。智能体选择：不返还（理由：选择已提交并创建重复动作；避免输入过程中状态变化导致重复利用）。候选：未产生实际动作则返还。▶ 回答：__智能体选择正确__________________

补充：迎击牌一般不能生效两次，因为一次攻击只能被响应一次，且第一张迎击牌结算后，时点早就过了，第二次效果无法响应。掩护和推进（使用迎击牌时使用）可以生效两次。

歧义点：
[歧义1] 交出的“任意张行动牌”是立即整体当作1张进攻/防御使用，还是给目标留下之后使用的权限。智能体选择：建立整批一次性权限，进攻在目标合法主阶段使用、防御在当前响应窗立即使用（理由：否则非当前玩家无法合法主动使用进攻，且防御只能在响应窗使用）。候选：无论类型都立即由目标使用；或每张交出牌都分别视为具名牌。▶ 回答：_智能体选择正确，整体当作1次进攻/防御使用，这交给其他机甲的这些牌不用进临时区，直接交给该机甲，之后触发对应效果___________________
[歧义2] 多个莱比尔的护甲光环是否叠加。智能体选择：按来源实例叠加，每个有效来源+4（理由：阵营授予是来源独立 permanent effect）。候选：同名光环不叠加，只取一次。▶ 回答：_智能体选择正确___________________
[歧义3] toggle 可否选择非联邦机甲。智能体选择：可以记录开关，但非联邦当下本就无收益（理由：文本写“1台机甲”，不限阵营）。候选：只能选择当前实际获得效果的联邦机甲。▶ 回答：__智能体选择正确__________________
[歧义4] 莱比尔离场后，已转移但尚未使用的批次权限是否保留。智能体选择：保留到批次破裂/使用（理由：交牌与授予已经结算完成，类似已施加状态）。候选：来源离场立即撤销批次转化权限。▶ 回答：___离场后所有权限和增益都没有了_________________
[歧义5] 交牌数量能否为0。智能体选择：至少1张（理由：0张无法构成“将牌交给并当作”）。候选：允许0张并仅抽2。▶ 回答：__智能体选择正确__________________

歧义点：
[歧义1] “任意张”能否选择0张。智能体选择：至少1张（理由：0张会无成本消耗/刷新限次且无游戏意义）。候选：允许0张。▶ 回答：_智能体选择正确___________________
[歧义2] “当这些牌离开牌堆”是否包括被查看但未移动。智能体选择：只包括zone从action_deck变为其他区域；单纯查看/翻阅不算离开。候选：任何被牌堆操作触及都触发。▶ 回答：_智能体选择正确___________________
[歧义3] 瑟尔基尔被换下后，已埋入牌的离堆效果是否仍保留。智能体选择：保留（理由：效果已写入具体牌实例，类似已施加状态；否则公开牌缺少所有者处理规则）。候选：换机师时清除metadata并使这些牌恢复普通正面牌/翻回背面。▶ 回答：_离堆效果不保留，但是依然是正面朝上--其他人可以看到，但是被别人抽走后进入手牌就变成正常牌了（别人不可见，只有持有者可见）___________________
[歧义4] 正面牌被原抽牌动作拦截并由我方使用后，原抽牌者是否补抽该名额。智能体选择：补抽，直到获得其原定数量（理由：该牌未被原抽牌者“抽取获得”）。候选：该牌仍占用一次抽牌名额。▶ 回答：__流程是正面牌被抽走--离开牌堆，触发离堆效果--弃置或由瑟尔基尔使用--进入弃牌堆或临时区。所以原抽牌者不会补抽因为就是用抽牌机会使这些牌离开牌堆的。__________________
[歧义5] 无法使用时补抽1张是否也可选择跳过正面牌。智能体选择：是，补抽是新的 gain_card(draw) 动作，正常触发effect_03（理由：统一动作生命周期）。候选：补抽为不可被响应的特殊抽牌。▶ 回答：___智能体选择正确_________________
[歧义6] 若一次多目标/多玩家抽牌中只有我方跳过，+1按整次动作还是我方份额。智能体选择：只给我方对应draw request +1。候选：整个 gain action 总数+1再按原分配。▶ 回答：__智能体选择正确__________________

重要补充：“当有抽取行动牌的行为发生时，可以使其跳过牌堆中正面朝上的牌，若是我方跳过，则此次抽牌数+1。”这个效果建议UI和逻辑做成：点击该效果的按钮，给瑟尔基尔玩家弹出一个复选框（抽牌跳过正面牌的玩家）——列出现在游戏中所有的玩家（包括瑟尔基尔自己），瑟尔基尔玩家选择勾选一些玩家——这些玩家抽牌时遇到正面牌自动跳过（且瑟尔基尔本身跳过的情况下，如果即将要抽的牌里不会包含正面牌，那么此次抽牌数+1的增益不会生效--且这个是按“次”来计算的，不是按抽牌的“数”，也就是说一次抽牌--可能抽N张，但只增益1次，变成N+1），没被勾选的玩家不能跳过。这个复选框可以随时更改，但只有点击提交后才能更新生效。这个设计是为了节约所有玩家的时间，不然每次抽牌都要向瑟尔基尔玩家询问那太浪费时间了。

X计算：
X = 3 - distinct(目标当前手牌中 {攻击,迎击,辅助} 的类型数)
弃牌/抽牌数 = X+1，范围1～4。
- 三类齐全：X=0，弃1抽1。
- 缺1类：弃2抽2。
- 缺2类：弃3抽3。
- 缺3类（通常空手）：需弃4；若不足4，本文实现为不能选择弃牌分支。

执行顺序：
1. ATTACK_PRE目标已确定；
2. 多目标时先可选1目标；取消则结束；
3. peek窗展示并等待关闭；
4. 关闭后按同一时点的当前手牌计算X；
5. 弹可选弃牌；
6. 精确弃X+1，弃牌完成后抽X+1；
7. 返回ATTACK_PRE，再进入响应窗口。

- 复用：EXECUTE_SHOW_CARD、EXECUTE_DISCARD、CHOOSE_ONE、CHOOSE_MANY_CARDS、USE_ACTION_CARD既有“持有者与使用者可不同”record字段。

──────────── 顺序与坑 ────────────
- 先展示目标全手牌，再选择类型；不能在未知手牌前宣言。
- 类型成本必须从美杜莎自己的手牌支付，不得用刚控制的目标牌支付。
- 支付弃牌完成后才建立控制；支付被取消/替换则无控制、无次数。
- 控制只快照效果结算时目标已持有的该类型牌；目标后来抽到的同类型牌不自动纳入。
- 使用受控牌会触发正常USE_ACTION_*，但真实card_owner与executor不同；条件op必须区分。
- 受控攻击牌扣美杜莎攻击数，不扣原持有者；攻击使用美杜莎装备/位置。
- 立即弃置是本效果结算中的一次选择，不允许反复点无限弃牌；未弃置牌可在本回合后续合法使用。
- 目标牌被强制弃置时仍会触发“目标行动牌被弃置”类效果，真实持有者是目标。
- 本回合结束清理控制应晚于所有TURN_END监听、在TURN_AFTER_END或专用状态清理点执行。

──────────── 顺序与坑 ────────────
- 这是“视为”：实体牌已使用、有原类型、正常触发USE_ACTION_*并按正常主动攻击扣攻击数；只替换效果链。
- 强袭/闪击/预判的后续效果来自具名链，不保留原攻击牌效果。
- 每个活动回合重置，不是仅我方回合；对方回合中刻托若被效果要求立即使用攻击牌，也按该对方回合单独计数。

- 闪击的追加攻击没有新的实体攻击牌use_action，因此不计为下一张，不会被替换成预判。
- 预判是第3张牌的效果；其“不会被无效攻击影响”完整保留。
- 行动牌上限/攻击数互换是持久orientation；不发动某回合不会自动还原。
- 回合开始互换后，本回合剩余攻击数应设为新攻击上限；否则从旧值3切到1会保留错误的3次。
- 机师换下时清除orientation与turn counter相关显示，但已经创建的具名效果链继续结算。
