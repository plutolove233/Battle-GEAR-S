## 一、游戏运行逻辑：Action Engine 效果体系

### 1.1 一个效果（ActionEffect）的组成

每张牌 = 1~N 个 effect。每个 effect 由以下部分构成：

| 部分 | 字段 | 说明 |
|------|------|------|
| 标识 | `effect_id` / `display_name` / `description` | effect_id 形如 `equipment_effect_NNN`（武器从 093 起） |
| 模式 | `mode` | `DIRECT`（发动立即执行）/ `LISTEN`（监听某动作某时点）/ `AVAILABILITY`（响应窗口可选牌） |
| 优先级 | `priority` | int，**大先执行**。常规=10；最低=-1；20/30 用于顺序保证 |
| 监听 | `listen_timing` + `listen_action_type` | LISTEN 专有：监听哪个动作类型的哪个时点 |
| 条件 | `set_conditions([{op,params}])` | 全部满足才触发 |
| 目标规则 | `set_target_rules([{rule}])` | 目标合法性 |
| 成本 | `set_costs([{cost_type,count,optional}])` | 触发前支付；`optional:true` 即「可以」 |
| 动作 | `set_actions([{type,params}])` | 按序执行的内容 |
| 依赖 | `requires_effect` | 必须先执行完此 effect_id 才触发 |
| 每回合1次 | `once_per_turn_key`+`once_per_turn_max` | 每回合限次 |
| 手牌永久 | `permanent_while_in_hand` | 手牌期间作永久监听器（武器牌通常 false，已装备才生效） |
| 可用条件 | `availability_condition`+`availability_priority` | AVAILABILITY 专有 |

**值解析**：`$payload.xxx` 读触发动作的 record（如 `$payload.target_id`/`$payload.attack_hit`/`$payload.effective_weapon_type`/`$payload.weapon_instance_id`）；`$binding_context.xxx` 读注册时注入的来源（武器牌：`card_instance_id`/`mech_id`/`player_id`/`slot_id="武器"`/`card_def_id`/`weapon_kind`）。

### 1.2 执行顺序

- 同一时点按 `priority` **降序**执行；同级**行动牌按注册序（先来后到）**，**装备牌按座次**（turn_order 序号）。
- `ATTACK_AT` 开响应窗口：AVAILABILITY 牌成可选；窗口关闭后才跑 regular 监听器。
- 「可以…」=`CHOOSE_ONE`+`optional:true` 或 optional 成本；多选=`CHOOSE_MANY_CARDS`；「每回合1次」=`once_per_turn_key`。
- 需玩家输入的动作（选目标/选牌/移动/弹窗）挂起父动作，串行机制保证多输入子动作依次执行。
- 状态效果（聚能/联合/锁定/折扣）有独立 LISTEN 监听器，施加时注册、移除时注销。

### 1.3 武器牌的植入模式

| 模式 | 触发方式 | 拆解首句点明 |
|------|---------|-------------|
| **永久监听 LISTEN** | set_equipment 设置到武器槽后注册永久监听器（binding_context 注入来源），弃置/替换时注销 | 「设置到武器槽后由 set_equipment 注册为永久监听器，监听\<动作类型>的\<时点>」 |
| **派生值实时重算** | **不注册监听器**，在武器威力/范围查询点调 helper 重算（如「每损伤威力-2」「威力=护甲×2」） | 「派生值型，不注册监听器。查询时实时重算：\<规则>」 |
| **DIRECT 主动** | 装备面板「发动」按钮/skill_bar 触发 `effect_fire` 动作（如维修臂/推进器/直攻免牌武器） | 「DIRECT，由装备面板发动按钮/skill_bar 触发」 |
| **AVAILABILITY 响应** | 响应窗口（ATTACK_AT）可选（如被光束/热能武器攻击时弃攻击牌减威力） | 「武器牌的可用条件（响应攻击）：优先级 N」 |

> 武器牌**没有「权限型」**（那是部件量产装卖出专用的）。武器牌极少用 `permanent_while_in_hand`（武器牌进手牌后通常只是待设置，不发动效果）。

## 二、既有件清单（优先复用，勿重复造）

拆解时**机制相同的优先复用**下列既有件；仅当确实无匹配时才提「需新增」，并在实现预告里写明命名（仿下述风格）+ 仿哪个既有范式。

### 2.1 时点（TimingConst）

- **效果模式**：`MODE_DIRECT` / `MODE_LISTEN` / `MODE_AVAILABILITY`
- **可用条件类型**：`AVAIL_RESPOND_ATTACK`（响应攻击）、`AVAIL_ALLY_IN_RANGE_TARGETED`（范围内友方被攻击）
- **回合**：`ROUND_START`、`TURN_BEFORE_START`、`TURN_START`（回复动力）、`TURN_AFTER_START`、`TURN_BEFORE_END`、`TURN_END`、`TURN_AFTER_END`
- **攻击**（武器牌最常用）：`ATTACK_BEFORE`（选武器后，可改威力/范围/武器类型）、`ATTACK_PRE`（选目标后，响应窗口前，可读 target_id/effective_weapon_type）、`ATTACK_AT`（发动攻击，响应窗口）、`ATTACK_AFTER`（伤害计算后，命中/未命中已定）、`ATTACK_SETTLE`（结算清理，可读最终损伤/HP）
- **使用行动牌**：`USE_ACTION_BEFORE`、`USE_ACTION_AT`（牌进临时区后）、`USE_ACTION_AFTER`、`USE_ACTION_SETTLE`
- **数值修正**：`STAT_MOD_BEFORE/AFTER/SETTLE`
- **移动**：`BASIC_MOVE_BEFORE/AT/AFTER/SETTLE`、`SINGLE_MOVE_SETTLE`
- **设置装备**：`SET_EQUIP_BEFORE/AT/AFTER/SETTLE`
- **获取牌**：`GAIN_CARD_BEFORE/AFTER/SETTLE`
- **弃置牌**：`DISCARD_BEFORE`、`DISCARD_AFTER`（牌在 tmp_zone，离场诱发在此触发）、`DISCARD_SETTLE`
- **效果发动**：`EFFECT_FIRE_BEFORE/AFTER/SETTLE`
- **生命变动**：`HP_CHANGE_BEFORE/AFTER/SETTLE`
- **损伤变动**：`DAMAGE_CHANGE_BEFORE/AFTER/SETTLE`
- **损伤转移窗口**：`DAMAGE_REDIRECT_WINDOW`（damage_change 放损伤前 fire，转移效果监听并弹汇总窗；盾牌吸收走此时点）
- **展示牌**：`SHOW_CARD_BEFORE/AFTER/SETTLE`
- `VICTORY_REACHED`

> **「聚能施加」时点**：当前体系无独立的「聚能时点」。`对此牌使用聚能时…` 类效果需在实现预告里明确：是监听聚能 action 的 `EFFECT_FIRE_AFTER`/`USE_ACTION_AT`，还是监听 `APPLY_ENERGY_TO_WEAPON` 原子动作后的某个时点——**这是武器牌的关键歧义之一，必须在拆解里给出选择并留回答行**（参见 `行动牌的效果与逻辑.txt` 中聚能牌的拆解）。

### 2.7 需新增件的命名规范

若某机制确实无既有件匹配，在「实现预告」逐条列【名称/语义/参数/仿哪个既有/登记点】，命名仿下述风格：

## 三、拆解输出格式（开发就绪·详细结构）

> 目标：让写代码的工程师能**直接照此写 ActionEffect + 测试**，无需二次拆解。每个效果必须给出可复制进代码的 GDScript 字面量（conditions/target_rules/costs/actions），外加自然语言解释、实现预告、顺序与坑、详细测试场景。

每张牌一节，结构如下（用 weapon_003 破甲狼爪 作完整范本，细节均已核实）：

```
═══════════════════════════════════════════════════════════
[武器牌 003] 破甲狼爪  （类型:近战  威力:15 范围:1 耐久:3 金币:3）
机制族：C.命中后额外损伤
═══════════════════════════════════════════════════════════
效果文本：此牌发动的攻击命中后可额外设置2损伤。
effect_ids：["equipment_effect_093"]

──────────── 效果拆解（equipment_effect_093）────────────
优先级：10
模式：LISTEN（永久监听）
植入：set_equipment 设置到武器槽后由 set_equipment_action._register_equipment_effects 注册 permanent listener，binding_context={card_instance_id, mech_id, player_id, slot_id="武器", card_def_id, weapon_kind="近战"}，装备弃置/替换/卖出时注销。监听动作类型 "attack" 的 ATTACK_AFTER 时点（伤害计算后，命中/未命中已定，payload.attack_hit 已就位）。

触发条件 conditions（逐条，GDScript 字面量 + 解释）：
  1. {"op": &"ATTACK_SOURCE_IS_SELF"}  -- 攻击的有效武器 == 本牌实例（attack.weapon_instance_id == $binding_context.card_instance_id），即「此牌发动的攻击」
  2. {"op": &"PAYLOAD_ATTACK_HIT"}      -- 本次攻击命中（$payload.attack_hit == true）

目标规则 target_rules：[{"rule": &"NO_TARGET"}]
成本 costs：[]
依赖/限次：无（requires_effect=&""、once_per_turn_key=&""、permanent_while_in_hand=false）

动作 actions（GDScript 字面量 + 逐行解释 + 执行顺序 + 人类UI）：
  [
    {"type": &"CHOOSE_ONE", "params": {
       "optional": true,
       "options": [{"label": "额外设置2损伤", "actions": [
          {"type": &"PLACE_DAMAGE_TOKENS", "params": {"count": 2, "target": &"attack_target"}},  # 在攻击目标机甲上按损伤放置优先级额外放2损伤

    }},
  ]
  执行顺序：ATTACK_AFTER 主损伤放置完成后，CHOOSE_ONE 弹窗挂起 attack 为 waiting_effect_action；玩家确认 -> PLACE_DAMAGE_TOKENS 放2损伤 -> attack 继续 ATTACK_SETTLE。取消 -> 不放，attack 继续。
  人类 UI：命中时弹 CHOOSE_ONE 二选一窗（"额外设置2损伤" / 取消）。取消=不放，攻击正常结算。

值解析：$binding_context.card_instance_id（本牌实例）、$payload.attack_hit（是否命中）、$payload.target_id（攻击目标机甲）。

──────────── 实现预告 ────────────
复用：
  - 条件 op：复用 ATTACK_SOURCE_IS_SELF、PAYLOAD_ATTACK_HIT（均已实现）。
  - 原子动作：复用 PLACE_DAMAGE_TOKENS、CHOOSE_ONE（均已实现）。
  - 派生值：无（威力15/范围1 是 stats，由 set_equipment 正常计入武器槽）。
  - JSON effect_ids：["equipment_effect_093"]（落码时同步，现 JSON 作废）。
  - UI 接线：复用既有 CHOOSE_ONE 弹窗（choice_panel），无需新面板。
（若需新建，逐条写：需新增 op/动作/helper 的【名称/语义/参数/仿哪个既有/登记点】+【JSON effect_ids: from->to】+【UI 接线：新弹窗 or 复用哪个】。）

──────────── 顺序与坑 ────────────
- 优先级 10 理由：常规诱发效果。与其他「命中后」武器/部件效果共存时按座次排序。若与 attack 主损伤放置时序冲突（PLACE_DAMAGE_TOKENS 在主放置之后），需测试确认 ATTACK_AFTER 时点主放置已完成。

场景b：命中 -> 选取消 -> 不额外放
  前置：同 a。
  操作：弹窗选取消。
  断言：目标损伤 == 主攻击损伤（无额外）；weapon_003 未动；攻击正常。
场景d：未命中 -> 不弹窗
  前置：玩家用 weapon_003 攻击但未命中（伤害为0/闪避）。
  操作：攻击结算。
  断言：不弹窗；无额外损伤。
场景e：用别的武器攻击 -> 不触发
  前置：玩家武器槽另有武器B，用B攻击命中敌方。
  操作：用B攻击。
  断言：effect_093 不触发（ATTACK_SOURCE_IS_SELF 不满足）。

歧义点：
[歧义1] 「额外设置2损伤」实现方式
  选择：PLACE_DAMAGE_TOKENS(target=attack_target, count=2)（主放置后额外放2枚，走全局放置优先级）。候选：MODIFY_ATTACK_MARKERS(+2)（改 attack 标记数，随主放置一起放）。▶ 回答：____________________

═══════════════════════════════════════════════════════════
```

### 格式要点（必须遵守）

1. **conditions / target_rules / costs / actions 必须给 GDScript 字面量**（StringName 用 `&"..."`），工程师可直接粘进 `set_conditions([...])` / `set_actions([...])`。`CHOOSE_ONE`/`CHOOSE_MANY_CARDS` 的 `options` 逐层展开到内层 actions。
2. **每个动作附行内注释**（`#`）说明它改什么字段/调什么，附自然语言「输入：发动方/触发来源/目标/数量/原因」。
3. **执行顺序**：多动作时写清先后与挂起点（哪个子动作会把父动作置 waiting_effect_action）。
4. **派生值型**（如 26/27 每损伤威力-2、40 威力=护甲×2 范围=动力、14/15 攻击次数衰减）：不写 conditions/actions，改写「helper 名 + 接入点（武器威力/范围查询点）+ 公式（统计口径：本牌损伤数/机甲护甲/机甲动力/攻击次数计数器）」。
5. **DIRECT 主动**（维修臂/推进器/直攻免牌/形态切换）：写「触发入口（装备面板发动按钮/skill_bar -> effect_fire）+ conditions（IS_OWNER_MAIN_PHASE 等）+ costs + actions + once_per_turn_key」。
6. **AVAILABILITY 响应**（被名响应）：写「availability_condition + availability_priority + 触发时点（ATTACK_AT）+ conditions + costs + actions」。
7. **复合效果**（一张牌多个不相关效果，如 11 光束斩舰刀=命中后自损伤 + 攻击时威力+3结算后自损伤；26 大型光束炮=每损伤威力-2 + 攻击时自损回复威力+2）：**拆多个 effect_id**，每个独立一节「效果拆解」，JSON effect_ids 列全。
8. **需新增件**：在「实现预告」逐条列【名称/语义/参数/仿哪个既有/登记点】。能复用就复用，别造重复件。
9. **测试场景**：每张牌至少给「正常发动 / 取消 / 条件不满足」3 类；复合、易错或新机制牌再加边界场景（如与其他效果共存、离场、重复触发、冷却清除、聚能交互、盾牌减伤、直攻免牌不耗攻击牌）。每个场景写清：前置（谁装什么于哪槽、敌方状态、回合/动力/手牌、is_human）、操作（按步：谁做什么 -> 哪个时点触发 -> 弹什么窗 -> 选什么 -> 继续）、断言（具体到字段名与期望值，如 `attack.record["extra_might"]==-5`、`zone=="equipment_discard"`、`slot.equipped_card==null`、监听器已注销、武器威力数值等）。
10. **歧义点**：凡有多种读法处必留 `[歧义N] ... ▶ 回答：____________________` 行。

## 四、歧义回答行格式

凡有效果文本存在多种读法处，**必须**留回答行（已并入上面每张牌的「歧义点」）。格式：

`[歧义N] <歧义点描述> 智能体选择：<你选的读法>（理由：…）。候选：<其他读法简述>。▶ 回答：____________________`

▶ 回答行留空 = 人类同意你的选择；不同意则人类在此行改写裁定。**不臆断**。武器牌典型歧义：
- 「聚能时」的触发时点（聚能 action 的哪个时点 / APPLY_ENERGY_TO_WEAPON 后）
- 「额外设置N损伤」放目标（PLACE_DAMAGE_TOKENS）还是改攻击标记（MODIFY_ATTACK_MARKERS）
- 「在此牌上设置损伤」是代价（先放再发动）还是后果（发动后放）
- 「可直接攻击不需要攻击牌」是否消耗本回合攻击次数、是否走正常 attack 时点链
- 「不能攻击」如何拦截（攻击发起校验 / 武器选择过滤）
- 冷却 flag 存哪（牌 counter / mech status）、何时清除
- 盾牌「全部损伤移至此牌」是否覆盖陷阱损伤、减伤（-1/-2）作用于转移量还是最终放置
- 「威力变为护甲×2」是派生值（实时重算）还是快照（发动时设定）
- 「每攻击1次威力-4」计数器粒度（每张武器独立 / 全局）、回合结束未用判定的「未用」口径
- 形态切换模式状态如何持久化与恢复
- 「弃攻击目标2张行动牌」目标手牌为空/不足时处理
- 复合效果是否拆多 effect_id、各 effect 顺序与 priority

## 五、输出文档结构

按**类型**组织三组：近战（01-15）、远程（16-30）、特殊（31-40）。组间用分隔线。每张牌按「三」的完整结构输出（效果拆解 / 实现预告 / 顺序与坑 / 测试场景 / 歧义点）。同组内效果文本完全相同的牌（如 06/07/21/22 同为「同区域额外2损伤」、14/15 同为等离子螺旋矛效果、29/30 同为冷却+聚能、31/35/38 同为盾牌吸收）：可引用首张的拆解（写「拆解同 [武器牌 XXX]」），但 **effect_ids 与测试场景仍逐张列出**（不同牌实例/数值的断言可能不同）。

**输出末尾**：给一份《effect_id 总览表》，三列 `[effect_id | 机制族+一句话语义 | 共用牌编号]`，按 effect_id 升序。这是落码时同步 JSON 的依据。

**处理范围**：40 张全部产出。若单次输出过长被截断，停在当前类型组末尾，等用户发「继续」从下一组接续。

## 六、硬约束

1. **唯一权威**：提供的 4 份文档（规则书/行动牌效果与逻辑/各动作生命周期与时点/装备牌武器全部信息）。冲突以文档为准；**武器 TXT 优先于现 JSON**（现 JSON 作废）。不以本提示词的既有件清单为准（清单仅供复用参考，若与文档冲突以文档为准）。
2. **全面弃 hook**：只用 Action+时点体系，不碰旧 hook。消息层走时点+日志。
3. **先 PvP 人类玩家 + UI**：逻辑/UI 要对任意数量人类玩家可复用；AI 逻辑暂不管。
4. **逐效果独立实现**：同型效果机制不同就拆独立 effect_id，接受少量重复；但**机制相同优先复用既有 op/原子动作/effect_id**，新建仅当确实无匹配。
5. **数据层**：effect_ids 数组手工维护，不重新生成；武器从 093 起分配，文末给总览表。
6. **不臆断**：歧义必留回答行，不私自裁定。
7. **GDScript 字面量精确**：conditions/actions 等给的字面量必须能直接粘进代码（StringName 用 `&"..."`、字典/数组语法正确、嵌套层级清晰）。
8. **PvP 可复用**：所有弹窗/输入路径假设多方人类玩家，不硬编码「玩家1」；响应窗口、直攻、形态切换等均按「当前操作人类玩家」路由。

## 七、关键坑（武器牌拆解时须正确处理）

- **「此牌发动的攻击」识别**：条件必含 `ATTACK_SOURCE_IS_SELF`（attack.weapon_instance_id == binding_context.card_instance_id）。不带此条件的「被攻击时」效果（如被名响应 01/02/16/17）用 `SELF_MECH_IS_ATTACK_TARGET`。
- **触发时点选择**（武器牌最易错）：
  - 「攻击时，可以使威力/范围+N」「需要额外消耗动力才能攻击」= **ATTACK_BEFORE**（选武器后，可改 extra_might/extra_range/武器类型，先于目标选择）。
  - 「指定目标时」「被指定为攻击目标时」= **ATTACK_PRE**（选目标后、响应窗口前）。
  - 「命中后」= **ATTACK_AFTER**（伤害计算后，命中已定）。
  - 「攻击结算后」「结算后」= **ATTACK_SETTLE**（清理阶段，可读最终损伤/HP）。
  - 「打出/使用攻击牌时」= **USE_ACTION_AT**。
- **武器威力修改的三种路径**（拆解须选对并说明）：
  - ① 改本次攻击：`MODIFY_ATTACK_MIGHT`/`MODIFY_ATTACK_RANGE`（写 attack.record.extra_might/extra_range，仅本次攻击有效，不改武器基础值）——用于「此牌攻击时威力+N」。
  - ② 改武器基础值：`MODIFY_WEAPON_POWER`/`SET_WEAPON_STATS`（持久改武器威力，跨回合）——用于「每攻击1次威力-4」「回复威力」。
  - ③ 派生值实时重算：helper 接入武器威力查询——用于「每损伤威力-2」「威力=护甲×2」。
  - **不可双计**：同一加成只能走一条路径。参考既有教训：神莺虚拟武器虚拟 range 不在 `_get_weapon_stats` 预加狙击加成（由 `_step_select_weapon` 统一加，避双计）。
- **自损伤放置**：`PLACE_DAMAGE_TOKENS` 指向自身 slot；自损伤达到耐久会触发武器破损弃置流程（与部件一致），弃置时注销本牌监听器——拆解须在「顺序与坑」说明自损伤→耐尽→弃置的连锁。
- **盾牌吸收**：监听 `DAMAGE_REDIRECT_WINDOW`，覆盖攻击与陷阱损伤；减伤（35:-1/38:-2）作用于转移量。须测试与部件损伤转移效果（联邦右臂/机动右臂）共存时的顺序。
- **直攻免牌**（32/36/39）：DIRECT -> EXECUTE_ATTACK 路径须明确是否消耗本回合攻击次数、是否走完整 attack 时点链（ATTACK_BEFORE/PRE/AT/AFTER/SETTLE）、武器选择是否跳过。对照 `各动作的生命周期与时点.txt` 的 attack 动作。
- **武器冷却 / 不能攻击**（10/29/30）：须新增「攻击发起校验」拦截——武器选择阶段过滤掉冷却中/被锁不能攻击的武器，或在 attack action 校验条件里查 flag。冷却 flag 清除时机：下个我方回合结束 / 聚能施加。
- **聚能时点**：`对此牌使用聚能时` 类效果须明确监听哪个时点（聚能 action 的 EFFECT_FIRE_AFTER 或 USE_ACTION_AT），且只对本武器生效（条件 ATTACK_SOURCE_IS_SELF 的等价：聚能目标武器 == 本牌）。
- **派生值型不注册监听器**：武器威力/范围查询点实时重算；计数器型（攻击次数衰减 14/15）需在牌上维护 counter，攻击成功后递增、回合结束按条件重置。
- **复合效果拆多 effect_id**：如 11/12（命中后自损伤 + 攻击时加成结算后自损伤）、26/27（派生威力 + 攻击时回复）、13（额外耗动力 + 可再耗动力加成）、24（减目标动力 + 条件额外损伤）、34（主动动力 + 迎击时动力）须拆多个 effect_id，各自注明 priority 与时点，确保顺序正确。
- **离场诱发**：武器因自损伤耐尽弃置时，监听 `DISCARD_AFTER` 的效果（若有）按 reason=damage_durability 过滤防循环。
- **PvP 路由**：所有弹窗（CHOOSE_ONE/形态切换/盾牌吸收/直攻目标选择）按当前操作人类玩家路由，不硬编码玩家序号；参考既有 `_effect_popup_owner_pid` 机制。
