## 一、游戏运行逻辑：Action Engine 效果体系（机师牌专版）

### 1.1 机师牌在 Action Engine 中的定位

- 机师在 `GameSetupService` 设置到机甲的 `pilot` 槽（`slot_id="pilot"`，`slot_kind=PILOT`），整局常驻。
- **机师效果注册**：仿装备的 `set_equipment_action._register_equipment_effects`，在机师设置时把每个 effect 按 `mode`/`listen_timing` 注册为 **permanent listener**，`binding_context = {card_instance_id, mech_id, player_id, slot_id="pilot", card_def_id}`。DIRECT 主动效果也注册（供 skill_bar 扫描出按钮）。
- **换机师支持**：机师可中途更换（少见但存在）。换机师 = 注销旧机师牌的所有 permanent listener（按 `card_instance_id`，复用 `timing_engine.unregister_permanent_listeners_for_card`）+ 注册新机师牌效果。机师牌本身不进弃牌堆。
- 机师效果目前仅在**旧系统** `GeneratedPilotEffects.gd`（legacy `CardEffect`、大量 `CUSTOM_EFFECT_CHECK_TEXT` 占位）。本次拆解产出的是**新系统 `ActionEffect`** 规格，将落在 `scripts/action_core/GeneratedPilotEffects.gd`（新）或并入 `GeneratedActionEffects.gd`。

### 1.2 一个效果（ActionEffect）的组成

每个 effect 由以下字段构成（`scripts/action_core/ActionEffect.gd`）：

| 字段 | 说明 |
|------|------|
| `effect_id` / `display_name` / `description` | effect_id 形如 `pilot_017_effect_01a`（沿用 JSON 既有 effect_ids，分支用 a/b/c） |
| `mode` | `DIRECT`（主阶段主动执行）/ `LISTEN`（监听某动作某时点）/ `AVAILABILITY`（响应窗口可选牌） |
| `priority` | int，**大先执行**（数值越大越先）。常规=10；最低=-1；20/30 用于顺序保证；**上限 30**（勿用 100/80 等超标值） |
| `listen_timing` + `listen_action_type` | LISTEN 专有：监听哪个动作类型的哪个时点（`listen_action_id` 一般留空） |
| `conditions` | `[{op, params}]` 全部满足才触发 |
| `target_rules` | `[{rule, params}]` 目标合法性 |
| `costs` | `[{cost_type, count/amount, optional}]` 触发前支付；`optional:true` 即「可以」 |
| `actions` | `[{type, params}]` 按序执行 |
| `requires_effect` | 必须先执行完此 effect_id 才触发 |
| `once_per_turn_key` + `once_per_turn_max` | 每回合限次（`once_per_turn_max=2` 即每回合 2 次） |
| `once_per_game_key` | **本局游戏限次**（**新增字段**，见 2.5） |
| `permanent_while_in_hand` | 手牌期间永久监听（行动牌用，机师牌不用） |
| `availability_condition` + `availability_priority` | AVAILABILITY 专有 |

**值解析**：`$payload.xxx` 读触发动作的 record；`$binding_context.xxx` 读注册时注入的来源（机师牌：`card_instance_id`/`mech_id`/`player_id`/`slot_id="pilot"`/`card_def_id`）。

### 1.3 机师效果的四种形态

| 形态 | 触发方式 | 拆解首句点明 |
|------|---------|-------------|
| **永久监听 LISTEN（被动）** | 机师设置后注册 permanent listener，监听某动作类型的某时点 | 「机师设置后注册 permanent listener，监听 \<动作类型> 的 \<时点>」 |
| **DIRECT 主动** | 主阶段 skill_bar 按钮 -> `effect_fire` 动作 | 「DIRECT，主阶段 skill_bar 按钮触发。conditions 含 IS_OWNER_MAIN_PHASE」 |
| **AVAILABILITY 响应** | 响应窗口（ATTACK_AT）可选 | 「AVAILABILITY，响应窗口可选。availability_condition=...」 |
| **派生值/权限型** | 不注册监听器，查询时实时重算 helper / 由特定面板识别 | 「派生值型，不注册监听器。查询点 \<MechState.xxx> 实时重算：\<规则>」或「权限型，由 \<面板> 识别」 |

### 1.4 执行顺序

- 同一时点按 `priority` **降序**执行（数值大先）；同级按注册序（先来后到）。
- **「并」/ 未说明 = 同时执行**；**「之后」= 前一个效果执行完再执行下一个**（拆解时必须在 actions 顺序与挂起点上写清）。
- `ATTACK_AT` 开响应窗口：AVAILABILITY 牌成可选；窗口关闭后才跑 regular 监听器。
- 需玩家输入的动作（选目标/选牌/移动/弹窗）挂起父动作，串行机制保证多输入子动作依次执行。

### 1.5 关键语义（机师牌核心，必须正确处理）

#### (a) 当作X（转化，出牌前）
- 机师消耗 N 张行动牌，获得 1 张**「虚拟转化牌」**（非行动牌、**无类型**），使用该虚拟牌 = **使用 X 的效果**。
- 使用条件**遵循 X**：
  - X 为攻击类（强袭/猛击/破甲/双连/进攻）→ 需范围内有攻击目标 + **消耗 1 次回合攻击数**（=**主动攻击**）。
  - X 为迎击类（反击/疾行/回避/识破/掩护）→ **必须响应对我方的攻击**（响应窗口，AVAILABILITY）。
  - X 为辅助类（维修/聚能/推进/联合/设陷/补给/锁定/觉醒/回收/回忆/折扣）→ 主阶段使用。
- 虚拟牌是攻击则**触发 ATTACK_\* 时点**，但**不触发 USE_ACTION_\***（转化不是「使用行动牌」）。
- 被转化的 X 的效果链（如强袭的 effect1 DIRECT + effect2 LISTEN）由转化直接引出执行。
- **「使用X时Y」类加成**：当**该机师**使用 X 的效果时触发 Y--**含转化虚拟牌与真实 X 牌两种来源**，仅对该机师有效，不波及其他机师。

#### (b) 视为X（替换，出牌后）
- 已使用出行动牌后（**有使用行动牌动作、有类型、已计回合攻击数**），将原效果**抹掉换成 X 的效果**。
- 一张牌的效果可被「视为」**多次洗**，按 priority 决定最终效果（主动攻击型 priority 一般比被动反击防御型高，后洗的覆盖先洗的）。
- 与当作的区别：当作是出牌前转化（无牌类型、不算使用行动牌）；视为是出牌后替换（牌已打出、已计攻击数）。

#### (c) 立即使用
- 「获得牌并立即使用」「立即使用 1 张攻击牌」→ **经完整 action 链打出**（攻击牌 → 发起 attack 动作）。
- 效果引出的攻击 = **被动攻击**，**不计回合攻击数**（与联合额外攻击同），**但仍需范围内有目标**。
- 主动攻击 = 玩家自发、无效果引导的攻击（武器攻击、投掷式飞弹、当作转化攻击）。

#### (d) 每回合N次 vs 我方回合N次
- **「每回合N次」** = 任意玩家一个回合内 N 次（在对方回合触发就占对方那回合额度；下一回合重置）。
- **「我方回合N次」** = 每个我方回合 N 次（仅我方回合可触发/计数）。
- 「本局游戏1次」= `once_per_game_key`（见 2.5）。

#### (e) X 变量
- 「X 初始为 0，X+1」类变量为**本局持续累积**（不随回合重置），**绑定该机师牌实例**（`card_instance_id`），不同机师的 X 分开计算。
- 有上限的标上限（如 pilot_008 X 最大 5）。pilot_028 的「宣言」每轮可改，X 本局累积。

#### (f) 阵营全队效果
- 「场上所有 X 阵营的机师牌/机甲框架获得…」= 作用于**场上所有该阵营机甲**（同阵营对局则双方都中，不限敌我）。
- 「取消或恢复 1 台机甲获得上述效果」= 场上**任意 1 台**（不限敌我）可被 toggle。

#### (g) 范围
- 「X 格范围内」= **六角距离 X 环**（`_HexGrid.distance`，odd-q offset），与攻击范围（BFS 地形感知）不同；**绿格只算 1 格，不额外计 1 动力/范围**。

#### (h) 还原威力（pilot_015）
- 「还原威力为攻击武器原本数值」**不新增原子动作**（动作与时点绑定，新增不合适）。改在 **attack record 上动手脚**：以 LISTEN 监听 ATTACK_BEFORE/ATTACK_PRE，把当次攻击的有效威力重置为武器基础威力（剥离 extra_might 等修正）。怎么方便怎么来。

#### (i) 请求我方（pilot_024/081/083）
- 范围内的**其他机甲**（请求方）在其回合内获得 1 个可点击的「请求」技能按钮。
- 请求方点击 → 给**机师拥有者**（被请求方）弹效果窗「是否同意执行此请求？」→ 同意则被请求方执行该效果（费用由被请求方支付），拒绝则不执行。
- 建模：机师效果向范围内其他机甲**授予 1 个 active 能力**（请求按钮），点击触发跨玩家同意弹窗。

### 格式要点（必须遵守）

1. **conditions / target_rules / costs / actions 必须给 GDScript 字面量**（StringName 用 `&"..."`），工程师可直接粘进 `set_conditions([...])` / `set_actions([...])`。`CHOOSE_ONE`/`CHOOSE_MANY_CARDS` 的 `options` 逐层展开到内层 actions。
2. **每个动作附行内注释**（`#`）说明改什么字段/调什么，附自然语言「输入：发动方/触发来源/目标/数量/原因」。
3. **执行顺序**：多动作写清先后与挂起点（哪个子动作把父动作置 waiting_effect_action）；「之后」必须体现为顺序。
4. **派生值型**：不写 conditions/actions，改写「helper 名 + 接入点（MechState.get_armor/get_total_power / RangeCalculator / MapService）+ 公式（统计口径）」。
5. **DIRECT 主动**：写「skill_bar 按钮 + conditions（IS_OWNER_MAIN_PHASE 等）+ costs + actions + once_per_turn_key/max」。
6. **AVAILABILITY 响应**：写「availability_condition + availability_priority + 触发时点（ATTACK_AT）+ conditions + actions」。
7. **当作/视为**：明确标注是「当作（出牌前转化，无类型，遵循X使用条件，攻击类消耗回合攻击数）」还是「视为（出牌后替换，已计攻击数）」，并写清引出/替换的 effect 链。
8. **复合效果**（一机师多个不相关效果）：**拆多个 effect_id**，每个独立一节，JSON effect_ids 列全。
9. **需新增件**：在「实现预告」逐条列【名称/语义/参数/仿哪个既有/登记点】。能复用就复用。
10. **测试场景**：每张牌至少给「正常发动 / 取消 / 条件不满足」3 类；复合、当作/视为、请求、地图、新机制牌再加边界场景。每个场景写清：前置（谁设什么机师、敌方状态、回合/动力/手牌/攻击数、is_human）、操作（按步：谁做什么 -> 哪个时点触发 -> 弹什么窗 -> 选什么 -> 继续）、断言（具体到字段名与期望值）。
11. **歧义点**：凡有多种读法处必留 `[歧义N] ... ▶ 回答：____________________` 行。

## 七、关键坑（拆解时须正确处理）

- **当作 vs 视为**：当作=出牌前转化（虚拟牌、无类型、不算使用行动牌、攻击类消耗回合攻击数=主动攻击）；视为=出牌后替换（已计攻击数）。详见 1.5(a)(b)。
- **主动攻击 vs 被动攻击**：当作转化攻击/武器攻击/飞弹=主动（消耗回合攻击数）；立即使用/联合额外攻击=被动（不消耗，但需范围内有目标）。详见 1.5(c)。
- **「使用X时Y」覆盖范围**：含当作转化 + 真实X牌 + 视为替换为X，仅对该机师有效。需用 USED_NAMED_TYPE_IS 检测（2.5-6），不能只靠 USE_ACTION_AT（会漏转化）。
- **每回合 vs 我方回合**：「每回合N次」=任意玩家回合N次；「我方回合N次」=仅我方回合N次。详见 1.5(d)。
- **X 变量绑定实例**：本局累积，按 card_instance_id 分开。详见 1.5(e)。
- **阵营全队含对手**：「场上所有X阵营」含对手同阵营；toggle 1 台不限敌我。详见 1.5(f)。
- **范围=六角环距离**：不是攻击范围 BFS；绿格不额外计。详见 1.5(g)。
- **还原威力不新增动作**：在 attack record 上重置。详见 1.5(h)。
- **请求=跨玩家同意**：请求方点按钮 -> 被请求方（机师拥有者）弹同意窗。详见 1.5(i)。
- **机师可换**：注册 + 注销路径都要（按 card_instance_id）。
