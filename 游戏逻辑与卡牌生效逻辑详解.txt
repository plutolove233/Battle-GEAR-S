================================================================================
第一部分　整体架构与两条效果系统
================================================================================

游戏运行在 Godot 4.6，主场景 res://scenes/app/app_root.tscn，1536×768。
核心数据流：
  rule/*.xlsx → tools/export_rule_data → data/*.json → DataRegistry →
  CardDatabase(→CardDef) → 各系统运行时读取

当前代码里**并存两套效果系统**，这是理解全貌的关键：

┌──────────────────────────────────────────────────────────────────────────────┐
│ 系统            │ 位置                         │ 状态   │ 用在哪              │
├──────────────────────────────────────────────────────────────────────────────┤
│ Action Engine   │ scripts/action_core/         │ 主系统 │ 行动牌、装备牌效果  │
│ (新)            │ scripts/action_defs/         │        │ 所有玩家/游戏动作   │
│                 │ GeneratedActionEffects.gd    │        │                    │
│                 │ GeneratedEquipmentEffects.gd │        │                    │
├──────────────────────────────────────────────────────────────────────────────┤
│ Hook/Effect     │ scripts/effect_core/         │ 兼容层 │ 机师牌效果(121张)   │
│ Engine (旧)     │ GeneratedPilotEffects.gd     │ 待删   │ DamageTokenService │
│                 │                              │        │ 的部分hook调用     │
└──────────────────────────────────────────────────────────────────────────────┘

重要事实：
- 行动牌(24张)效果全部走新 ActionEffect 体系（GeneratedActionEffects.gd）。
- 装备牌(42张N部件 + R/SR/SSR)效果走新体系（GeneratedEquipmentEffects.gd）。
- 机师牌(88张数据/121个效果定义)效果仍走旧 CardEffect+hook 体系
  （GeneratedPilotEffects.gd），且大量用 CUSTOM_EFFECT_CHECK_TEXT 占位
  （即只写了描述文本、原子动作尚未真正实现）。
- DamageTokenService 仍调用旧 effect_engine.fire_hook(HOOK_DAMAGE_DEALT)。

入口约定：所有玩家/游戏动作都通过
  context.action_service.execute(action_type, params)
统一发起，不再往 EffectEngine 加新逻辑。


================================================================================
第二部分　Action Engine（新系统）核心机制
================================================================================

------------------------------------------------------------
2.1 统一入口 ActionService（scripts/action_core/ActionService.gd）
------------------------------------------------------------
三个对外方法：
  execute(action_type, params)        创建并执行动作
  continue_action(action_id, input)   恢复等待输入的动作
  cancel_action(action_id)            取消动作（递归取消子树）
  execute_sub_action(action_def, payload, parent_action)  效果产生的子动作

init_factories() 注册 13 个动作类型工厂（见第三部分）。

子动作分两类：
- 原子动作（_is_atomic_action == true）：不创建 Action 实例，直接分发到
  context.game_actions.xxx。共约 80+ 种原子操作（MODIFY_ATTACK_MIGHT、
  ADD_STATUS、DRAW_ACTION、PLACE_DAMAGE_TOKENS、ROLL_D6…）。
- 非原子子动作（EXECUTE_ATTACK/EXECUTE_STAT_MODIFY 等）：创建 Action 实例，
  显式登记 parent_action_id / pending_sub_action_ids 父子关系，由 ActionEngine 驱动。

几个"特判"原子动作直接写父动作 record（不走 game_actions）：
  MODIFY_ATTACK_MARKERS   → parent.record["extra_markers"] += delta
  MODIFY_ATTACK_MIGHT     → parent.record["extra_might"]   += delta
  MODIFY_ATTACK_RANGE     → parent.record["extra_range"]   += delta（支持 min_value 钳制）
  SET_ATTACK_EFFECTIVE_WEAPON_KIND → parent.record["effective_weapon_type"]
  MODIFY_ATTACK_TEMP_ARMOR→ 原 attack 动作 record["temporary_armor_bonus"]
  RESPOND_ATTACK          → 原 attack 动作 record["responded"/"counter_attacked"]
  NEGATE_ATTACK           → attack.negated = true
  SET_ATTACK_UNNEGATABLE  → attack.unnegatable = true
  CANCEL_PARENT_ACTION    → 沿 parent 链找指定类型祖先并取消
  DISCARD_SELF_AND_REDUCE_ATTACK_MARKERS → 弃本牌 + record["extra_markers"] -= max
  DRAW_EQUIPMENT_AND_IMMEDIATELY_SET → 抽装备并立即设置到原区域
  OFFER_DAMAGE_REDIRECT   → 实际由 TimingEngine 拦截弹窗

------------------------------------------------------------
2.2 Action 基类（Action.gd）
------------------------------------------------------------
字段：
  action_id, action_type, source(来源dict), record(随步骤更新的记录),
  steps[], current_step_index, state, context,
  negated(被识破无效), unnegatable(不可被识破),
  pending_sub_action_ids[](等待的子动作), parent_action_id,
  _execute_attack_ran(诊断用)

状态：pending / running / waiting_input / waiting_timing /
      waiting_sub_action / completed / cancelled

每个 step = {step_name, timing_point, handler}
  timing_point 在 handler 执行**前** fire（重要：先 fire 时点再跑 handler）

------------------------------------------------------------
2.3 ActionEngine（ActionEngine.gd）驱动流程
------------------------------------------------------------
execute_action(action):
  1. 守卫：已 completed/cancelled 拒绝重复执行（修 bug3b 二次结算）
  2. state=running
  3. _run_step_loop 从 current_step_index+1 开始
     每个 step：
       a. 若有 timing_point → TimingEngine.fire_timing（可能让 action 暂停成 waiting_timing）
       b. 若 attack 被 negated → 跳到 settle step
       c. 调 handler(action) → 返回 result
       d. result.need_input=true → 暂停 waiting_input，发 action_needs_input 信号
       e. result.sub_action_created=true → 暂停 waiting_sub_action 等子动作
  4. 全部跑完 → _complete_action

continue_action(action_id, input_data):
  - 仅 waiting_input/waiting_timing/waiting_sub_action 可恢复
  - waiting_input 恢复时**重新执行当前 step handler**（回填玩家输入）
  - waiting_timing/waiting_sub_action 恢复时**不重跑**当前 step（避免重复 fire）
  - 然后继续后续 step

cancel_action：递归取消子树 → 标 cancelled → 通知父动作从等待列表移除 → cleanup。

父子等待：子动作 _complete_action 时用 call_deferred 通知父动作
（避免清理过程中递归）；父动作所有子动作结束后 continue_action 恢复。

------------------------------------------------------------
2.4 TimingEngine（TimingEngine.gd）时点与监听
------------------------------------------------------------
fire_timing(timing, action):
  1. payload = action.record 副本 + action_id/action_type
  2. 收集监听器：permanent_listeners（装备/机师持续效果）
     + temporary_listeners（行动牌临时效果、状态效果、手牌AVAILABILITY）
     按 listen_action_type / 绑定 action_id 过滤
  3. 分离出 AVAILABILITY 模式效果 → 若有则开响应窗口、暂停动作并 return
  4. 常规监听器按 priority 升序（同优先级按注册 seq "先来后到"）依次 _execute_effect
  5. 任一监听器让 action 进 waiting_timing（如请求目标选择）则中断循环

监听器注册：
  register_permanent_listener(timing, effect, binding_context)
    — 装备 set_equipment 时注册；binding_context 携带
      {card_instance_id, mech_id, player_id, card_def_id}
  register_temporary_listener(timing, action_id, action_type, effect, ...)
    — 行动牌使用时注册，绑定到 action_id
  register_status_listener — 状态施加时注册，status_id 关联
  register_availability_listener — 手牌迎击牌注册为响应窗口可用牌

注销：
  unregister_permanent_listeners_for_card(card_id) — 装备弃置/替换
  unregister_listeners_for_action / _for_card / _for_status

每回合1次控制（once_per_turn_key）：
  _once_per_turn_used = { "card_id:key": {turn_number: used_count} }
  触发前检查 used >= once_per_turn_max 则跳过；执行后 +1。
  scope=turn_number，换回合自动失效。

挂起效果（_pending_effect）：optional 弃牌/目标选择/二选一/损伤转移
  需要玩家输入时存 {effect, payload, phase}，弹窗；
  resume_pending_effect 注入输入后续跑 _execute_effect / _pay_costs + _execute_actions。

------------------------------------------------------------
2.5 _execute_effect 执行链（单个效果如何生效）
------------------------------------------------------------
顺序：
  1. requires_effect 检查（依赖的前置效果是否已执行）
  2. _check_conditions（ConditionChecker）
  3. once_per_turn 检查
  4. _check_targets（TargetChecker）；需要玩家选目标则 _request_target_selection 挂起
  5. _check_costs（CostChecker）；optional 弃牌则 _request_optional_discard 挂起
  6. _pay_costs
  7. _execute_actions：遍历 effect.actions[] 逐个执行
     - REGISTER_LISTEN → 注册临时监听器
     - CHOOSE_ONE → 二选一/多选一，未选则挂起 choose_one_effect 弹窗
     - OFFER_DAMAGE_REDIRECT → 损伤转移弹窗（AI 自动决策，玩家挂起 redirect_select）
     - 其它 → execute_sub_action(act, payload, action)
  8. 标记 once_per_turn used
  9. _mark_effect_executed（供 requires_effect 查询）
     若迎击牌效果，同步标记到原 attack 动作（跨动作 requires_effect）

来源解析 _make_binding_from_effect：
  优先 payload.binding_context（装备 permanent listener），
  退回 action.source（行动牌 DIRECT/临时监听）。
  装备效果触发时 action 是被监听时点所属动作（如 attack），
  其 source 是攻击方而非装备牌——故装备 condition 必须从 binding_context 取。


================================================================================
第三部分　13 种动作类型（scripts/action_defs/）
================================================================================
每种动作 setup_steps() 定义步骤数组 [{step_name, timing_point, handler}]。
TimingConst 定义所有时点常量（见 2.x 已列）。

------------------------------------------------------------
3.1 attack（attack_action.gd）攻击动作 ★核心
------------------------------------------------------------
8 步：
  ① extract_attack_info  无时点   记录 attacker_mechs/attack_source/target_count
  ② select_weapon        ATTACK_BEFORE  选武器（已指定则直接用）；记录
       weapon_might/weapon_range/effective_weapon_type
  ③ select_target        ATTACK_PRE     选目标并验范围；
       有效范围 = weapon_range + extra_range（最低1）
  ④ execute_attack       ATTACK_AT      初始化 responded/counter_attacked=false（幂等）；
       【响应窗口在此 fire】：AVAILABILITY 迎击牌暂停动作
  ⑤ check_hit            无时点   hit = 目标在有效范围内且未 destroyed；negated→hit=false
  ⑥ calculate_damage     ATTACK_AFTER   伤害=max(0, weapon_might+extra_might - (护甲+temp_armor))
       损伤=floor(攻击威力/5) + extra_markers - damage_reduction
       【破甲 effect2/防御等在此后写入 extra_markers/temp_armor，统一一次结算】
  ⑦ apply_damage         无时点   产生子动作 hp_change（伤害）+ damage_change（损伤）；
       损伤放置者：被响应→目标玩家，否则→攻击者玩家
  ⑧ settle               ATTACK_SETTLE  弃攻击牌/迎击牌，写 attack_resolved/attack_miss 日志

伤害公式（BattleMath 一致）：
  damage = max(0, 攻击威力 - (目标护甲 + 临时护甲) - damage_reduction)
  markers = floor(攻击威力 / 5) + extra_markers    （攻击威力含 extra_might）
  每 5 点攻击力 = 1 枚损伤标记

武器来源：frame_base_weapon_N（机甲框架自带武器，trim_prefix 解析索引）
  或 CardInstance（设置的武器装备牌）。

------------------------------------------------------------
3.2 use_action_card（use_action_card_action.gd）使用行动牌 ★核心
------------------------------------------------------------
5 步：
  ① validate_card    USE_ACTION_BEFORE  验证牌可用、记录 mech_id；
       攻击牌检查 can_attack()；纯 AVAILABILITY 牌禁止主动打出
  ② card_to_temp_zone 无时点  从手牌移除→temp_zone；
       注销手牌 AVAILABILITY 监听；注册 DIRECT/LISTEN 效果临时监听器
  ③ fire_use_action_at USE_ACTION_AT  空 handler（修"框点两次不生效"拆分）
  ④ execute_effects  USE_ACTION_AFTER  执行 DIRECT 效果；
       攻击牌 attack_count_this_turn+=1；
       注册延迟 LISTEN（bind_to_sub）到 DIRECT 产生的 attack 子动作；
       若有未完成子动作 → sub_action_created 暂停
  ⑤ settle           USE_ACTION_SETTLE  非虚拟牌进行动弃牌堆

LISTEN 效果三种绑定：
  bind_to_attack_action=true → 绑到原 attack 动作（迎击牌 effect2，如反击的反击攻击）
  bind_to_sub=true           → 延迟绑到 DIRECT 产生的子动作（如破甲 effect2 绑 attack A）
  否则                       → 绑到本 use_action_card 动作

------------------------------------------------------------
3.3 set_equipment（set_equipment_action.gd）设置装备牌 ★核心
------------------------------------------------------------
7 步：
  ① extract_info     无时点
  ② select_slot      无时点  选区域（已指定则直接用）
  ③ discard_old      无时点  弃置旧装备：先注销旧装备 permanent_listener，
       再 discard_card(reason=equipment_replace)，slot.equipped_card=null
  ④ remove_damage    SET_EQUIP_BEFORE  按新装备耐久度移除区域内损伤
  ⑤ place_equip      SET_EQUIP_AT   装备设置到区域；
       注册装备效果（_register_equipment_effects）；
       PART 槽重算 max_power 并调整当前动力
  ⑥ activate_equip   SET_EQUIP_AFTER  空步（效果已注册）
  ⑦ settle           SET_EQUIP_SETTLE  fire 时点

_register_equipment_effects：
  查 GeneratedEquipmentEffects.get_effects_for_card 取 effect_id 列表。
  - 派生值型效果（002/008/014/016/021/023）不注册监听器，实时重算。
  - DIRECT 主动效果（无 listen_timing）注册到"以 effect_id 为虚拟时点"，
    供 equipment_panel/skill_bar 扫描主动触发。
  - LISTEN 效果注册到 effect.listen_timing，携带 binding_context。
  弃置/替换时 unregister_permanent_listeners_for_card。

------------------------------------------------------------
3.4 basic_move（basic_move_action.gd）基础移动
------------------------------------------------------------
4 步：extract_target(BASIC_MOVE_BEFORE) → consume_power(BASIC_MOVE_AT) →
      move_position(BASIC_MOVE_AFTER) → settle(BASIC_MOVE_SETTLE)
动力消耗：NORMAL=1，GREEN=2，RED 不可通过。
通过 MapService.move_mech_to_hex 改位置。

------------------------------------------------------------
3.5 single_move（single_move_action.gd）单次移动
------------------------------------------------------------
迎击牌（回避/疾行/反击/识破）的移动用此。
支持 power_fraction（如 0.5=半动力）、use_current_power（全动力）、loop_until_cancel、max_cells。
时点 BASIC_MOVE_SETTLE / SINGLE_MOVE_SETTLE。

其余动作类型（每个 setup_steps 定义步骤+时点）：
  stat_modify       STAT_MOD_BEFORE/AFTER/SETTLE      数值修正（护甲/动力/威力）
  gain_card         GAIN_CARD_BEFORE/AFTER/SETTLE     获取牌（指定/随机/弃牌堆）
  discard_card      DISCARD_BEFORE/AFTER/SETTLE       弃牌（含 from_target 从目标手牌弃）
  steal_action_card 抢牌（识破 effect1：from_attacker 偷1）
  effect_fire       EFFECT_FIRE_BEFORE/AFTER/SETTLE   按 effect_id 发动效果
  hp_change         HP_CHANGE_BEFORE/AFTER/SETTLE     生命变动（damage_change 前 fire DAMAGE_REDIRECT_WINDOW）
  damage_change     DAMAGE_CHANGE_BEFORE/AFTER/SETTLE 损伤变动；
                    place_damage_tokens 前 fire DAMAGE_REDIRECT_WINDOW（损伤转移窗口）
  show_card         SHOW_CARD_BEFORE/AFTER/SETTLE     展示/翻看牌


================================================================================
第四部分　回合 / 轮次流程
================================================================================

TurnService（scripts/services/TurnService.gd）

start_turn(player_id)：
  1. active_player_id=player_id, phase=TURN_START
     player("player") 回合则 turn_number+=1
  2. 清 once_per_turn_used / turn_counters / sell_equipment_count；
     mech.attack_count_this_turn=0
  3. 位次1玩家回合开始前 fire ROUND_START
  4. fire TURN_BEFORE_START
  5. fire TURN_START；restore_power(full) 回满动力
  6. 抽 2 行动牌（每张 register_hand_card_availability 注册 AVAILABILITY 监听）
  7. 抽 1 装备牌
  8. gain_gold(2)
  9. phase=MAIN
  10. fire TURN_AFTER_START

end_turn(player_id)：
  1. phase=TURN_END
  2. fire TURN_BEFORE_END
  3. fire TURN_END；event_timer_service.tick_on_turn_end 推进事件计时
  4. 弃超 action_card_limit 的行动牌（pop_back）
  5. 弃全部未设置装备牌
  6. _clean_this_turn_durations：清 THIS_TURN 状态（含 POWER_MODIFIER 反算动力）
  7. fire TURN_AFTER_END
  8. victory_service.check_victory()

RoundService：1v1 轮换 turn_order，player 为位次1。

时点全览（TimingConst）：
  回合：ROUND_START / TURN_BEFORE_START / TURN_START / TURN_AFTER_START
        / TURN_BEFORE_END / TURN_END / TURN_AFTER_END
  攻击：ATTACK_BEFORE / ATTACK_PRE / ATTACK_AT / ATTACK_AFTER / ATTACK_SETTLE
  使用行动牌：USE_ACTION_BEFORE / USE_ACTION_AT / USE_ACTION_AFTER / USE_ACTION_SETTLE
  移动：BASIC_MOVE_BEFORE/AT/AFTER/SETTLE，SINGLE_MOVE_SETTLE
  装备：SET_EQUIP_BEFORE/AT/AFTER/SETTLE
  其它：STAT_MOD_* / GAIN_CARD_* / DISCARD_* / EFFECT_FIRE_* / HP_CHANGE_*
        / DAMAGE_CHANGE_* / SHOW_CARD_*
  特殊：DAMAGE_REDIRECT_WINDOW（损伤转移）、VICTORY_REACHED

响应窗口机制：
  attack 的 ATTACK_AT 时点 fire 时，TimingEngine 收集 AVAILABILITY 监听器
  （手牌中的迎击牌，availability_condition=RESPOND_ATTACK 等）。
  有可用牌 → response_window_opened 信号 → ActionUIBridge 弹响应面板 →
  attack 暂停 waiting_timing。
  玩家选迎击牌 → handle_response_selection 发起 use_action_card 子动作
  （注入 attack_action_id），attack 切 waiting_sub_action 等其完成。
  玩家取消（空选）→ continue_action 恢复 attack 继续 check_hit/apply_damage/settle。
  重入保护：_handled_response_actions 按 action_id 去重，防双信号重复触发。


================================================================================
第五部分　战斗系统
================================================================================

- HexGrid：轴向坐标 q,r；24×8 地图。
- RangeCalculator：BFS 范围计算（地形感知：GREEN=2动力，RED阻挡）。
- BattleMath：damage=max(0,attack-armor)，markers=floor(attack/5)。
- 攻击流程见 3.1。
- 损伤放置（DamageTokenService）：
    place_one_token_at_slot（玩家逐枚选槽位）
    place_damage_tokens（AI 自动放置）
  优先级：已装备部件 > 已装备武器 > 空部件 > 空武器 > 其他
  规则：有装备槽位时，空槽位不可放置。
  每放一枚：region_damage_tokens+1，有装备则 equipped_card.damage_tokens+1，
  然后 equipment_break_service.check_equipment_broken。
  注：DamageTokenService 仍调旧 effect_engine.fire_hook(HOOK_DAMAGE_DEALT)。
- 装备破坏：损伤 ≥ 耐久度 → EquipmentBreakService 走破坏流程（注销→弃置）。
- 地图标记：GOLD（D6 得金）、EVENT（抽事件）、TRAP（范围1爆破 伤害3 损伤1）。

胜利条件（VictoryService.check_victory）：
  - 机甲 destroyed → 对方胜
  - HP≤0 → 对方胜
  - 回合数 ≥ turn_limit（默认12，GameConfig.MAX_TURNS=30，temp_values 可覆盖）
    → 比 HP，HP 高者胜；HP 相同则进攻方不利（判负）
  达成时 fire VICTORY_REACHED 时点。


================================================================================
第六部分　卡牌生效逻辑（逐个）—— 行动牌（24张，新体系）
================================================================================
来源：GeneratedActionEffects.gd
每张牌 → 1~3 个 ActionEffect，模式 DIRECT/LISTEN/AVAILABILITY。
状态效果（聚能/联合/锁定/折扣）有独立 LISTEN 效果，施加状态时注册为临时监听器。

------------------------------------------------------------
1. 进攻 action_001  attack_basic_direct (DIRECT)
   动作：EXECUTE_ATTACK target_count=1。基础攻击牌，打1目标。

2. 强袭 action_002
   - assault_effect1 (DIRECT)：EXECUTE_ATTACK 打1目标。
   - assault_effect2 (LISTEN, ATTACK_AFTER, priority=-1)：
     条件 ATTACK_WAS_RESPONDED（被迎击）→ EXECUTE_SINGLE_MOVE 全动力循环移动。

3. 猛击 action_003
   - smash_effect1 (DIRECT)：EXECUTE_ATTACK。

================================================================================
第十一部分　关键设计要点与已知坑（代码注释佐证）
================================================================================
1. 时点在 handler 前 fire：故 ATTACK_AT 的 responded 字段在 execute_attack
   handler 执行前还没写入——强袭 effect2 改听 ATTACK_AFTER 才能读到 responded。

2. 攻击二次结算 bug3b：已加幂等守卫（_execute_attack_ran + execute_action
   拒绝重跑 completed/cancelled 动作）。某些 deferred 通知路径可能二次驱动。

3. 迎击响应窗口去重：_handled_response_actions 按 attack action_id 去重，
   防 response_selected/availability_effect_selected 双信号重复触发导致
   同一迎击牌用两次、误绑到 single_move 子动作、攻击卡死不结算。

4. 状态机恢复约束：continue_action 仅接受 waiting_input/timing/sub_action，
   故父动作恢复前不能先置 running（会被拒、卡死）。

5. 装备效果来源：permanent listener 触发时 action 是被监听时点所属动作（如 attack），
   其 source 是攻击方而非装备牌。装备 condition 必须从 binding_context 取
   card_instance_id/mech_id/player_id。

6. 派生值型装备效果（联邦/帝国头部、重甲头部、损伤阈值动力）不注册监听器，
   在 MechState/MechSlotState 查询时实时重算，避免 hook 顺序问题。

7. USE_ACTION_AT 拆两步：原 card_to_temp_zone 同时挂时点+handler 会导致
   时点在牌进临时区前 fire，CHOOSE_ONE 挂起跳过 handler→牌不进临时区、
   效果不注册。拆为 card_to_temp_zone(无时点) + fire_use_action_at(空handler)。

8. 机师效果仍是旧体系且大量占位：当前机师牌效果大部分未真正生效，
   迁移到 Action Engine 是后续工作。

9. 损伤转移窗口 DAMAGE_REDIRECT_WINDOW：damage_change 动作在 place_damage_tokens
   前 fire，转移效果（联邦右臂/机动右臂）监听并弹汇总窗选转移点数，
   AI 自动决策转移保护装备。

10. 每回合1次用 once_per_turn_key + card_instance_id 区分来源，scope=turn_number
    自动失效。
